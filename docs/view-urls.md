# 表示条件と記事の共有URL（F02）

アドレス欄のURLをコピーすると、月・日刊の並び順・検索語・フィルターを新しいタブや再読み込みで復元する。静的な相対パス配信で動作し、外部サービスや保存領域は使わない。

## URLの形式

例（GitHub Pagesのプロジェクトページでも、localhostの `/` でも同じ規則）:

```text
/ai-watch/?month=2026-09&order=asc&q=Codex
/ai-watch/?sample=&month=2026-09&order=asc&category=AIコーディング&category=AIモデル&feed=Claude+Code+Releases&feed=OpenAI+News&from=2026-09-30&to=2026-10-02
/ai-watch/?sample=&month=2026-10#article-AGgAdAB0AHAAcwA6AC8ALwBhAC4AZQB4AGEAbQBwAGwAZQAv
```

2つ目の日本語は説明用。実際のURLは `URLSearchParams` がパーセントエンコードする。3つ目のIDは `https://a.example/` の例で、記事がデータ内になければ一覧と案内を表示する。

| 要素 | 規則 |
| --- | --- |
| `month` | 実在する月の一覧から選択。未指定は最新月、未存在の月は案内して最新月に補正。絞り込み中も元の日刊の月を保持 |
| `order` | `asc` のみ古い順。`desc` は既定でURLでは省略。検索結果は従来どおり取得日降順 |
| `q` | 前後の空白除去・連続空白の統合。最大500 UTF-16コード単位。超過分は切り詰めて案内 |
| `category` / `feed` | 同じキーを繰り返す。値の完全一致で選択、重複を除きコード単位順にソート。カンマは値の一部。各200コード単位・各50選択まで。既存インデックスにない候補は取得成功後に解除して案内 |
| `from` / `to` | 実在する `YYYY-MM-DD`、両端を含む取得日。片側のみも可能。不正日は除去、逆転は両方を解除して案内。公開日で補わない |
| `sample` | 存在すればサンプル専用。すべての生成URLで維持し、同じ相対パスの `samples/` だけを読む |
| `#article-…` | 記事の安定ID。現在の条件のまま対象へ移動。その他の不明なパラメータは保存しない |

単一値のパラメータが重複した場合は先頭を使い案内する。空値の条件は省略する。補正は `replaceState` で一度だけ行い、新たな履歴を追加しない。検索インデックス取得失敗時は未知候補と決めつけず、条件と記事IDを保ってF05の再試行を出す。

F01と同じ「カテゴリ内OR・情報源内OR・条件間AND」、検索語なしの絞り込みを維持する。検索語だけ解除／フィルターだけ解除／すべて解除もそれぞれURLに反映され、全解除後は保持していた月・日刊の並び順へ戻る。

## 履歴の更新規則

- 月・並び順・チェックボックス・解除・サイト内共有リンクは、変更があるとき `pushState`。
- 検索の入力はIME確定後・250ms debounceで適用する。最初の適用は `pushState`、同じ編集セッションの続きは `replaceState`。Backで入力開始前の状態へ戻れる。1文字ごとの履歴は作らない。
- Enterで検索を確定し、次の編集を別セッションにする。未適用ならそこで適用、適用済みなら履歴を増やさない。入力欄の `change`（通常は離脱時）でも編集セッションを閉じる。
- 取得日入力も同じく最初はpush、その続きはreplace。`change` で確定する。不正・入力途中の日付の間は最後の有効なURLを保持し、F01のエラーを表示する。`invalidDateInput` は保存しない。
- フィルター確定時は未適用の検索入力も取り込む。IME変換中は確定済みの検索語だけを使い、変換途中の結果通知を出さない。
- `popstate` はタイマー・変換状態・旧通信の `loadToken` を無効にしてURLを復元し、新しい履歴をpushしない。データ取得成功後の補正だけreplaceする。
- サンプル／本番をまたぐ手動の履歴遷移では再読み込みし、キャッシュを混ぜない。

`view-url.js` は読み取り・正規化、書き出し、ID生成の純粋関数。`app.js` の `updateViewState()` とURL復元経路がUI・履歴・通信を同期する。記事データや遅延応答を履歴の状態に保存しない。

## 記事IDと移動

`safeUrl()` で検証・正規化した **完全な元記事URLのUTF-16バイト列をbase64url** にし、`article-` を付ける。短いハッシュを使わず、異なるURL同士の衝突を避ける。クエリ・フラグメントも元記事の同一性に含める。URLが不正／欠落、または8192コード単位超の場合は共有リンクを付けず、通常の記事カードを表示する。

日刊内に同じURLが複数出た場合、元ログの順番で最初を基本ID、2件目以降を `~2`、`~3` とする。`~` はbase64urlに含まれないため基本IDと衝突しない。並び順変更でIDは変わらない。検索インデックスは既存のURL重複除去を維持するため、最初の基本IDのみを使う。日刊の重複記事URLを検索結果に手動で持ち込んでも、別の記事へ読み替えない。

「このサイト内で共有」は同じサイトの通常リンクで、外部の「元記事を開く」と区別する。クリック／Enterで移動、修飾キーで新しいタブ、ブラウザのメニューでリンクをコピーできる。クリップボードAPIに依存しない。URLには検索語・絞り込みが含まれ、履歴や共有先に残ることを画面のヘルプでも案内する。

日刊では読み込み後に該当日を展開する。検索／絞り込みでは必要な50件ページを追加してから対象へスクロールし、記事見出しにフォーカス、既存の読み上げ領域で記事名を通知する。取得失敗ならIDを保って再試行する。存在しない／現在の条件に非表示／インデックス未収録の対象は、現在の通常一覧を残して案内し、存在しないフラグメントだけreplaceで外す。条件を広げたり別の記事へ移動したりしない。
