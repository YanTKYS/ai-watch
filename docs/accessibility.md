# 閲覧画面のアクセシビリティ（F06）

## 見出しと移動

| 表示 | 見出しの関係 |
| --- | --- |
| サイト名 | h1 |
| 収集状況 | h2（視覚的には隠した領域名） |
| 日刊 | 月 h2 → 日付 h3 → カテゴリ h4 → 記事 h5 |
| 検索 | 検索結果 h2 → 記事 h3 |

日付のh3はネイティブの `details/summary` 内に置く。Tabで日付へ移動し、EnterまたはSpaceで開閉できる。見出しレベルを変えても既存の文字サイズとカード配置を維持する。

ページで最初のTab操作により「本文へ移動」を表示する。Enterでメイン領域へ移動し、フォーカス枠を表示する。通常のTab順序へ余分な停止位置を増やさず、結果の見出し・追加記事の見出し・状態文には必要時だけプログラムでフォーカスできる。

記事タイトル・元記事・リリースのリンクは新しいタブで開く。記事一覧の前に一度だけ案内文を表示し、各対象リンクから同じ文を `aria-describedby` で参照する。リンク名を長い定型文で置き換えず、読み上げでも開き方を確認できる。安全なURL検証と `noopener noreferrer` は維持する。

## 通知

記事操作の通知は、常設の `view-announcement`（`role=status`、`aria-live=polite`、`aria-atomic=true`）にまとめる。可視の読み込み・失敗文は別の通常要素として残し、同じ失敗を二つのライブ領域から通知しない。

- 検索完了時は検索語・合計件数・表示件数を通知。0件も通知する。
- 追加表示では合計のうち何件を表示したかを通知する。
- 日刊表示へ戻ったときや月・並び順を変えたときは、月・件数・並び順を通知する。
- 読み込み失敗時は既存の通信/形式エラーの説明と再試行の案内を通知する。
- 正規化後の検索語が同じなら再描画・再通知をしない。

250ms debounceと日本語IME確定を維持する。入力が変わった時点で古い応答を無効にし、debounce待ちや変換中の古い件数・失敗を通知しない。変換開始時は既存のタイマーも止める。無効にした検索と同じ語へ戻った場合は、確定後に結果を表示し直せる。

F04の収集状況は、公開記録を示す独立したライブ領域のまま。検索や月切替はそこへ書き込まない。F04側も同じ文言を繰り返しDOMへ書き込まない。サンプルでは従来どおり本番状態を表示・取得しない。

## 操作後のフォーカス

| 操作 | フォーカス |
| --- | --- |
| 入力・通常の検索完了 | 入力欄から移動しない |
| 月・並び順の変更 | 操作中の選択欄から移動しない |
| 日付の開閉 | ネイティブsummaryに残る |
| 「さらに表示」、まだ次ページがある | 操作中のボタンに残る |
| 最後の「さらに表示」 | 消えるボタンから、今回追加した最初の記事見出しへ移る。次のTabでその記事リンクへ進める |
| 「再試行」待機中 | ボタンを残し、`aria-disabled` とハンドラで連続実行を防ぐ |
| 再試行が失敗 | ボタンに残り、再び操作できる |
| 再試行が成功 | ボタンを操作中なら結果のh2へ移る。見出しのない空ログ等は表示中の状態文へ移る |
| 再試行中に別の操作へ移った | フォーカスを奪い返さない。古い処理からの通知・移動も無効にする |
| クリア | 入力欄へ戻り、日刊表示を通知する |

再試行による月一覧→日刊の連続取得は、日刊が表示されるまで一つの操作として扱う。フォーカス枠はライト/ダーク双方の既存アクセント色を使う。

## 検証

`python -m unittest discover -s tests -v` は既存の非同期競合・F05・F04テストに加え、`test_app_accessibility.cjs` の12ケースをNode上で実行する。実際の `app.js` を用い、DOM構造、通知更新、フォーカス、旧応答、debounce、IME、0件/多数件、最終追加、再試行の失敗/成功、連続操作、クリア、サンプルを確認する。依存関係は追加しない。

ブラウザ検証では、320px/1280px、200%ズーム、ライト/ダークでTab・Shift+Tab・Enter・選択欄の矢印キーを使い、横はみ出し、スキップリンク、見出し、日付開閉、検索、追加表示、再試行、クリアを確認する。収集状況あり/状態ファイルなしも含め、実施結果と未確認事項は対応PRに記録する。

ARIAツリーと通知文の更新確認は、実スクリーンリーダーでの音声確認とは区別する。NVDA/VoiceOver等による実機確認では、日付summary内の見出し、リンクの説明、複数のpolite領域、成功後のフォーカス位置を重点的に確認する。

主要操作の実Chromium回帰は [E2Eの10ケース](browser-tests.md) でもPR CIから実行する。これは上記の音声・実IME評価を代替するものではない。


F02の「このサイト内で共有」は同じタブのサイト内リンク。新しいタブの共通案内は外部リンクだけを対象にする。共有先では日付/必要な結果ページを展開して記事見出しへスクロール・フォーカスし、既存の原子的な通知領域で記事名を伝える。対象がなければ一覧と案内を残す。詳細は [共有URL](view-urls.md) を参照。
