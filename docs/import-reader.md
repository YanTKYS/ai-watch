# Grok・Perplexityの原記録をPagesで読む

ページ上部の「公式ニュース」「Grok（X）」「Perplexity（週次）」で表示を切り替える。公式が既定で、公式の月選択・検索・絞り込み・共有URLは従来どおり。別ソースの閲覧中は公式専用の操作・収集状況を隠す。原記録を公式の日刊ログや検索インデックスへ採用する処理は追加しない。

## 表示内容と確度

- **Grok**: `imports/x/YYYY/x-YYYYMMDD.md`を日付の新しい順に選ぶ。タイトル、カテゴリー、投稿日時・投稿者、概要・注目点、元投稿リンク、原記録の確度を表示する。収集日時・対象期間は投稿日時と別に表示し、原記録の記載を補正・検証したとは扱わない。
- **Perplexity**: `imports/p/YYYY-Www.md`をISO週番号の新しい順に選ぶ。選択したレポートの対象週・調査日を本文上にも表示する。本文の見出し・段落・箇条書き・表・リンク・強調・コードを表示する。2026-W44の原記録は調査日2026-10-31、対象2026-10-26〜11-01で、完了した先週の調査とは表示しない。
- Grokは未検証の候補、Perplexityも一部未検証の可能性がある調査として案内する。原記録の「公式発表」等のラベルは保証ではない。重要な判断・脆弱性情報は元出典を確認する。原記録・本文の外部リンクは新しいタブで開く。

[Grokの2026年10月評価](grok-x-evaluation-2026-10.md)の訂正・未確認事項は引き続き有効。本機能は既に公開リポジトリへ保存された候補の**閲覧経路**であり、評価済み公式ニュースへの昇格・原記録の訂正ではない。利用条件や転載可否を確認済みにするものでもない。新たに保存する際も各サービス・原出典の保存/再配布条件を確認し、公開できる内容だけを置く。X投稿全文の取得・スクレイピング・転載、Brave結果の保存、Grok/Perplexityの追加実行はしない。

## Grokのカード表示

Grokは日付入り見出しを一つにし、件数（原記録）・収集日時・対象期間・収集元を短い共通ヘッダーへまとめる。日付選択・一覧更新・GitHub原記録へのリンクも一か所に置く。成功メッセージは画面の高さを取らずaria-liveで通知し、読み込み中・エラー・再試行は見える形で残す。

カードはタイトル→概要→注目点→カテゴリ・投稿者・投稿日時・確度・元投稿の順。1000px以上は2列、狭いPC・タブレット・スマートフォンは1列にする。本文は省略せず、新しい/未知の欄もカード末尾に表示する。タイトル・概要・元投稿がない場合は欠損を明示し、不正な元投稿URLは文字として残す。原記録の確度を当サイトの検証済み判定へ変えない。

Perplexityは1列の長文レポートを維持し、本文幅だけ96chへ広げる。表は独立した横スクロールのまま。ソース切替は通常のリンクをタブ風に表示し、現在位置とフォーカスを区別する。

画面比較（10/30の原記録、ローカルChromium、ダーク）: [PC変更前](images/grok-layout/before-desktop.png) / [PC変更後](images/grok-layout/after-desktop.png)、[375px変更前](images/grok-layout/before-mobile.png) / [375px変更後](images/grok-layout/after-mobile.png)。1280×900では最初のカードが上端932pxから437pxへ、375×900では1093pxから653pxへ移った。この原記録・表示環境での比較であり、他の日の文章量では異なる。ライト/ダークとも横はみ出しなしを確認した。API一覧だけローカルfixtureに置き換え、本文は既存原記録をそのまま配信した。

## ファイルの自動発見と配信

静的Pagesにディレクトリ一覧APIがないため、閲覧時にGitHubの[公開Repository Contents API](https://docs.github.com/en/rest/repos/contents#get-repository-content)を認証なし・読み取り専用で利用する。少人数での閲覧を想定した方式で、新しいワークフロー・有料API・APIキー・特権トークン・生成索引を必要としない。

1. Grokは`imports/x/`から年ディレクトリを列挙し、各年のファイルを取得する。Perplexityは`imports/p/`を列挙する。
2. ファイル種別、名前、実在する日付/ISO週、年とパスの一致を検査する。APIが返す`download_url`・`html_url`は使わず、検査した識別子から決まったパスだけを組み立てる。
3. 本文は**Pagesと同じオリジン**の相対パスから取得する。GitHub APIや別サービス経由で本文を取得するフォールバックは設けない。配信は既存の`.nojekyll`による静的Markdownを利用する。

新しいMarkdownを上記の命名規則でmainに追加し、Pages配信へ反映すれば、新規のページ読み込みか「一覧を更新」で発見する。フロントエンドに日付・週番号を追記する必要はない。Grokの新年ディレクトリ、Perplexityの新年の週番号にも対応する。内容の形式が変わる場合は表示の互換性を別途確認する。

一覧・本文の成功応答はページを開いている間だけキャッシュする。定期ポーリング・永続キャッシュはない。「一覧を更新」は一覧と選択本文を再取得し、「原記録を再試行」は失敗した読み込みをやり直す。APIのキャッシュ・配信反映による遅れが直ちに解消する保証はない。すでに日付/週を選択している場合、一覧更新後もその選択を保つ。

### 制約とトラブルシュート

| 状態 | 表示・対応 |
| --- | --- |
| APIが失敗・拒否・レート制限 | 空一覧とは扱わずエラーと再試行を表示。GitHub上の一覧/原ファイルへ移動できる |
| 命名規則に合うファイルが0件 | リポジトリの一覧にまだない旨と「一覧を更新」を表示 |
| 指定した日付/週が一覧にない・不正 | 最新レポートへ黙って置換せず、別選択・更新を案内。不正な入力から本文URLを作らない |
| 本文404 | API側の追加とPages配信の時間差も考慮し、「まだ配信されていない可能性」と再試行・GitHub原ファイルのリンクを表示 |
| 壊れた一覧、空本文、通信失敗・時間切れ | 検証不能を正常な0件と区別。成功した別ソースや公式記事は閲覧できる |
| 多数のファイル | Contents APIの1ディレクトリ上限1,000件に達した応答は完全な一覧とみなさず案内する。規模が増えたら索引方式等を別途検討する |

GitHubの[公開APIのレート制限](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)はアクセス元等の条件による。ブラウザからの公開API依存が増え、共有回線・頻繁な更新では制限に達しうる。通常、Perplexity一覧は1要求、Grokは年一覧1要求＋各年1要求。選択本文はPagesへの1要求。自動リトライや制限解除のための認証は行わず、時間をおいて明示的に再試行する。

1応答は1,000,000バイト、1要求は20秒を上限にする。年ディレクトリの一部が取得できない場合も完全な一覧や記事なしとして報告しない。GitHub APIが指すmainとPagesで配信中の版は一致するとは限らず、一覧に存在することだけで配信完了を判断しない。[公式収集・Pages配信の境界](collection-health.md#actionsでの記録と配信の境界)も参照。

別のリポジトリへ流用するときは`import-catalog.js`の固定したリポジトリ名・ブランチを見直す。ユーザー入力やAPI応答の任意のURLを接続先として受け入れない。

## URL・履歴・サンプル

```text
/ai-watch/?source=x&entry=2026-10-30
/ai-watch/?source=p&entry=2026-W44
```

`source=x|p`が表示元、`entry`が日付/週番号。省略時は一覧の最新を選び、URLへ反映する。切替と選択は履歴へ記録し、戻る/進む・再読み込みでも復元する。公式の既存パラメータと記事フラグメントは保持し、公式へ戻るとその条件で復帰する（[公式の共有URL](view-urls.md)）。原記録を公式の`article-`IDへ変換しない。

`?sample`では切替を隠し、本番のGrok/Perplexity一覧・本文を取得しない。`sample`と`source`を同時に指定しても公式のサンプルだけを表示する。

## 安全なMarkdown表示と実装の責務

- `import-catalog.js`: 命名・パス・経路検査、API一覧と同一オリジン本文の取得、応答上限とページ内キャッシュ。
- `import-markdown.js`: Grokの欄の解析と、限定したMarkdown構文の解析・DOM生成。日刊用`parser.js`を流用しない。
- `import-reader.js`: 切替・選択・状態・再試行と表示。切替前の遅い応答は別ソースの表示を上書きしない。公式との接点は`app.js`の経路切替だけ。

原記録は信頼しない入力。`innerHTML`・HTMLパーサー・eval・外部CDNは使わず、テキストと決めたDOM要素のみを作る。任意HTMLは文字として表示し、画像・iframe・イベント属性・スクリプトは埋め込まない。リンクは認証情報を含まないhttp/httpsのみで、危険なスキーム・相対URLはリンクにしない。未知・壊れたMarkdownは可能な範囲で文字として残す。完全なCommonMark/GFM実装ではなく、入れ子リストは平坦表示、相対リンク・画像・脚注等は対象外。

表・コードは幅内で横スクロールでき、見出し階層を飛ばさず表示する。切替は通常のナビゲーションリンク、日付/週の選択はネイティブselectを使い、Tab・Enterで操作できる。非表示の公式操作はフォーカス・読み上げ対象から外す。再試行成功後は、操作中のボタンが消える場合だけ見出しへフォーカスする。

## 検証と新規Markdown追加の再現

外部API・Xページ・Grok/Perplexityへ実接続しない。

```sh
python -m unittest discover -s tests
# 導入はbrowser-tests.mdを参照
npm run test:e2e
```

`tests/test_import_reader.cjs`は合成入力で命名・年跨ぎ・新規発見・URL・APIエラー・配信前404・応答上限・Markdown無害化等を検証する。`tests/e2e/imports.spec.cjs`はAPI/本文をfixtureへ差し替え、PC/スマートフォン×ライト/ダーク、キーボード、履歴、公式検索の復帰、空一覧、404の復旧、遅い応答、sample分離を検証する。実際の既存10/30・W44の原記録もローカルで表示確認し、内容は書き換えない。

新規追加の再現テストは`new filenames in a new year and week...`。最初の一覧から、API fixtureだけに`imports/x/2027/x-20270102.md`と`imports/p/2026-W45.md`を追加した応答へ切り替える。「一覧を更新」で新ファイルが出て、年を跨いだ本文選択・URL復元が動くことを確認する。アプリ本体・公式データ・索引へ日付を書き足さず、追加Markdownの発見を再現している。
