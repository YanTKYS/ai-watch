# 全期間の絞り込み（F01）

ヘッダーの「絞り込み」を開くと、カテゴリ・情報源・取得日を指定できる。キーワードなしでも利用でき、対象は最後に取得できた `data/search-index.json` の保存済み記事。公開サイト上の全ニュースや、インデックスに未反映の記事を検索する機能ではない。

## 条件と表示

- カテゴリ内の複数選択、情報源内の複数選択はOR（いずれか）。カテゴリ・情報源・取得日・検索語の間はAND（すべて一致）。未指定の条件は制限しない。
- 取得日は `retrieved` のYYYY-MM-DDを使い、開始日・終了日を含む。片方だけでも指定できる。元記事の `published`（公開日）は期間判定へ使わない。
- キーワードは従来のNFKC正規化、空白区切りAND・部分一致を維持する。リリースの抜粋や個別バージョン名も従来どおり検索できる。
- 条件が一つでもある間は全期間の結果一覧にし、取得日の新しい順・50件ずつ表示する。月と日刊の並び順は無効になる。取得期間と月選択の役割は別。
- 現在の条件は折りたたみの外に表示する。0件でも条件を残し、変更や全解除へ進める。検索語のみなら「検索結果」、フィルターがあれば「絞り込み結果」と表示する。

例: カテゴリ「AIコーディング」・情報源「Claude Code Releases」・取得日「2026-09-30〜2026-10-02」を選ぶと、両日を含む期間の該当記事を表示する。さらに検索語を入れると、その集合をキーワードでも絞る。候補名と記事は実際のインデックスにある場合にだけ表示される。

## 3種類の解除

| 操作 | 検索語 | カテゴリ・情報源・取得日 | 操作後のフォーカス |
| --- | --- | --- | --- |
| 検索欄の「クリア」（読み上げ名: 検索語をクリア） | 解除 | 維持 | 入力欄 |
| 「フィルターだけ解除」 | 維持 | 解除 | 絞り込みのsummary |
| 「すべての条件を解除」 | 解除 | 解除 | 入力欄 |

条件がすべて空になれば、絞り込み前に選んだ月・並び順の日刊表示へ戻る。日刊のデータが取得済みなら再取得せず使い、未取得ならその月を読む。日付の展開状態は従来と同じく、その月の最新日を初期展開する。

## 候補・取得失敗・旧データ

候補は `buildSearchEntries()` が読み取れた記事の `category` / `feed` から重複・空欄を除いて作り、固定表を新設しない。前後の空白は候補・条件の照合時に除く。結果を絞っても候補自体はインデックス全体から作った一覧を維持する。

初期の日刊表示ではインデックスを取得しない。初めて絞り込みを開いたとき、検索したとき、または条件を指定したときに読む。同時の要求は同じPromiseを使い、成功後はページ内でキャッシュする。候補を開くだけでは全期間モードへ切り替えない。

候補取得だけの失敗では日刊を維持し、パネル内の「候補を再試行」を案内する。全期間モードで取得に失敗した場合はF05の「再試行」を表示し、現在の条件を保って再取得する。失敗応答や壊れたJSONを正常な0件とは扱わない。

欠損・空欄のカテゴリ/情報源は候補に追加せず、その項目の条件を選んだときだけ対象外になる。取得日が欠損/不正でも期間の指定がなければ従来どおり読めるが、開始または終了を指定した場合は除外する。公開日による補完はしない。旧インデックスでもフィールドを追加・書き換えずに読める。

開始＞終了、存在しない日付や日付入力途中の状態は、エラーと `aria-invalid` で案内する。誤った期間で検索したり、エラーを0件として通知したりしない。

F04の収集/生成状態は独立して表示する。生成失敗の表示があっても、取得できる直近のインデックスで絞り込む。再試行はデータ取得の再試行で、収集やインデックス再生成を起動しない。キャッシュした索引を最新の公開版で読み直すにはページを再読み込みする。`?sample` はsampleの候補・記事だけを使い、本番状態を取得しない。

## 状態と回帰保護

`app.js` の `viewState` は `{ query, categories, feeds, from, to, invalidDateInput }`。検索語/日付は文字列、複数選択は文字列配列とし、`updateViewState()` に更新を集約する。`invalidDateInput` はnative date入力が途中でvalueを返せない場合のUIエラーフラグで、保存用の条件にはしない。取得済み記事・Promise・月のキャッシュは別で管理する。

DOMを使わない候補抽出・日付検証・絞り込みは `parser.js` に置く。キーワード判定は既存の `searchArticles()` を使い、記事順や採否を変更しない。F02で月・並び順も状態へ追加し、URLパラメータ・履歴・共有に接続する。ローカルストレージ等への永続化は行わない。

`loadToken` で古い結果/エラーを無効にし、入力の250ms debounceとIME確定を維持する。変換中のフィルター変更は条件だけ更新し、検索結果の描画・通知は確定後へ回す。候補の読み込み完了は検索結果や日刊の通知を上書きしない。

`tests/test_filters.cjs` の11ケースを通常のunittestから呼び、OR/AND、境界・月またぎ・欠損・不正日付、キャッシュ/失敗/再試行、3種類の解除、元の月と並び順、非同期競合、debounce/IMEを検証する。[Chromium E2E](browser-tests.md) にも320pxの代表操作と、取得失敗・不正期間の2ケースを追加した。外部APIや実データの書き換えは使わない。


表示条件のURL復元・戻る／進む・記事リンクは [F02の仕様](view-urls.md) を参照。
