# PLaMo Web検索の独立検証

本番への採用判断に向けた手動の評価だけを行う。オーナーがPRレビュー後に実APIを実行する。実装・単体テストではPLaMo APIや引用先へアクセスしない。

## 公式情報の確認（2026-10-27）

- [API利用方法](https://docs.plamo.preferredai.jp/ja/getting-started) と [APIリファレンスのWeb検索](https://docs.plamo.preferredai.jp/ja/api#web-検索) を参照。`POST https://api.platform.preferredai.jp/v1/chat/completions`、`plamo-3.1-prime`、Bearer認証、`web_search_options.search_context_size=low` を使う。
- 非ストリーミング応答の `choices[0].message.content` を短い要点にし、引用は `message.annotations[].url_citation` から抽出する。本文中のリンクを構造化引用として推測しない。`response_format` は引用が返らなくなるため使わず、検索と併用できない `temperature`・`n`・`tools` 等も送らない。
- トークン数は `usage` の3項目。Web検索回数は `plamo_usage_details` 内で `usage_type=web_search` の `token_consumed` の合計。欠落・不正・部分的な内訳は「不明」で、0やAPI要求数に置き換えない。`finish_reason=length` は打ち切りと案内する。
- [料金・データの扱い](https://docs.plamo.preferredai.jp/ja/pricing): 検索にはトークンとは別の費用があり、1回答で複数回検索しうる。Standardの検索単価キャンペーンは2027-01-31まで。Freeの入力・出力は保存・学習対象で、Web検索ではクエリや閲覧先URLが外部検索サービスへ送られる。個人情報を入力しない。
- [公式Chatマニュアル](https://docs.plamo.preferredai.jp/ja/chat#利用上限とデータの取り扱い) のFree Web検索は2026-11-30までの日次60回・月次200回という案内で、Deep Researchと共通。これをキー所有アカウントの残量や、将来のAPI無料保証とは扱わない。プラン・最新条件・アカウント全体の使用量はオーナーが実行前に確認する。
- [公式利用規約](https://plamo.preferredai.jp/info/terms) へのリンクは確認したが、調査ツールでは本文を取得できず、生成要点・引用URLの保存に関する個別条項は未確認。保存が無制限に許されるとは判断しない。オーナーはレビュー・実行前に最新条項と第三者出典の条件を確認し、許容できる場合だけ実行を選択する。

保存は短い生成要点と出典URL・タイトル・計測値に限定する。検索結果一覧・ページ本文・長文引用・reasoning・レスポンス全体は保存しない。Braveの検索結果・利用条件や既存保存仕様は変更せず、この検証のデータとも混ぜない。

## Actionsでの実行（レビュー後にオーナーが行う）

1. マージ後、Actionsの **PLaMo Web search probe (manual only)** → **Run workflow**。GitHubの新規手動ワークフローは既定ブランチにファイルが存在してから表示・起動できる。
2. `topic` で下表の固定テーマから1つ選ぶ（既定は `models`）。自由入力・複数指定・全テーマの自動巡回はない。`confirm_one_request=false` の既定では、テーマ・調査期間・プロンプト・設定・照合用seenスナップショット情報の計画レポートだけを作る。通信・無料枠消費は0。
3. 規約・費用・残量を確認して `confirm_one_request=true` を選ぶと、登録済みのRepository Secret `PLAMO_API_KEY` を実行ステップにだけ渡し、1 POSTを試行する。401/429/5xx/タイムアウトでも再試行しない。リダイレクトにも追従しない。
4. Job Summaryおよび **plamo-probe-実行ID-試行番号** Artifactの `report.md` / `report.json` を確認する。API失敗でも整形した報告を残し、ジョブは失敗として扱う。Artifact保持要求は**1日**。初回は3日を指定したが、リポジトリ上限により実効1日に短縮されたため、設定を実態に合わせた。保存期間の長期化は行わない。Job Summary・実行ログ・ダウンロード済みコピーは別管理で、これらの1日後の自動消去は保証しない。

自由入力のプロンプト・APIエンドポイント・モデル・ページング・クエリ展開・リトライ設定は設けない。`max_tokens=2048`、`reasoning_effort=none`、90秒タイムアウト、1MBの応答読み取り上限。これらは検索回数・入力トークン・費用の完全な上限ではない。並行起動は直列化するが、再実行は新たな1要求を消費する。日次・月次の永続カウンタやアカウント全体の使用量APIは利用しない。

キー・認証ヘッダー・HTTPエラー本文・未加工例外をログに出さない。レポートはフィールドを限定して生成し、既知のキーを伏せ、外部文字列をHTMLエスケープしたpre内で表示する。認証情報付き・非公開向け・不正URLは保存しない。URLを検証するための追加アクセスも行わない。

## 調査期間・再現用情報・比較の意味

日本時間の実行日を含む7暦日を調査する（両端含む、最終日は実行時点まで）。1回につき選択した1テーマだけを調べる。

| topic | 対象 |
| --- | --- |
| `models` | 生成AIの新しい基盤モデルの正式発表 |
| `coding` | AIコーディングツールの正式リリース・重要な機能追加 |
| `agents-mcp` | AIエージェント・MCPの正式リリース・重要な仕様変更 |
| `api-pricing-limits` | 生成AI APIの価格・利用上限・提供条件の公式な変更発表 |

プロンプトv2では開発元・提供元の公式告知を優先し、他テーマや二次解説で件数を埋めず、最大3項目の短い要点を求める。**公式発表日と、更新日・解説記事の公開日・検索エンジンの日付は別**として扱い、確認不能な日付を推測しないよう指示する。これは指示であり、実際の回答の事実検証ではない。

| 比較 | v1（初回） | v2（今回） |
| --- | --- | --- |
| 調査範囲 | 4テーマを1問にまとめる | 固定4択から1テーマ |
| 要点の要求 | 最大6項目 | 最大3項目 |
| 日付の指示 | 公開日を重視 | 公式発表日を更新日/記事公開日/検索日と区別 |
| API要求 | 最大1件・再試行なし | 最大1件・再試行なし |
| 品質 | 二次情報や期間外の候補が混在した | 実APIでは未検証。改善を保証しない |

新方式との実測比較はレビュー・マージ後にオーナーが明示実行する。テーマごとの比較も別々の手動実行であり、その都度料金・残量を確認する。自動比較・複数テーマの巡回・出典ページの追加取得は行わない。

UTC実行日時、選択テーマ（ID・表示名・対象）、日本時間の期間、モデル、固定パラメータ、プロンプト全文と版、`seen.json` のSHA-256/URL数を記録する。同じ入力でも生成結果・検索対象が同じになる保証はない。

- 同一回答内の引用を、元の文字列の完全一致で重複除去する。追跡パラメータ・フラグメント・末尾スラッシュも保持する。
- `data/seen.json` のキーと完全一致した数、採用済み/リリース統合URLとの一致、不採用URLとの一致、未記録の引用URL候補数 `new_url_candidates` を分けて表示する。**新規ニュース発見数ではない**。不採用として既知のURLを、新規候補や収集済み記事と誤表示しない。
- seenを読めない場合はAPIを呼ばず失敗する。既知URLを誤って新規と数えない。
- 引用は最大100 URL、タイトル160文字、回答は最大6行×160文字。上限超過・引用なし・使用量不明・打ち切りを案内する。
- これらはURL照合とプロバイダー申告値の集計。**一次情報性・公式発表日・期間適合性・重要度・新着性は未検証**とレポートの先頭に表示する。構造化引用があることやAPI成功は、これらの確認を意味しない。
- レポートJSONはschema version 2。テーマと `quality_verification` を追加し、旧 `citation_counts.new_candidates` は意味を明確にした `new_url_candidates` へ変更。品質の状態はすべて `unverified` で、モデルの主張や日付らしい文字列を自動認定しない。
- Markdownに引用番号付きの人手評価表、JSONの各引用に空の `human_review` を用意する。オーナーがコピーに一次情報性・公式発表日・期間内か・重要度・新着性・日付の種類・公式の根拠URL・メモを記録できる。`null` は未評価であり、否定判定や確認済みを意味しない。
- 日付・一次情報性・重要度は追加の外部アクセスで自動検証しない。人手評価も提供元・出典元の条件を確認した保存可能な範囲にとどめる。

## 初回実測と費用・品質の留意点

[初回実API実行 #40532535798](https://github.com/YanTKYS/ai-watch/actions/runs/40532535798)（旧v1、オーナー実行）はHTTP 200、API要求1回、Web検索1回、約14.19秒、入力**18,334**・出力727トークンだった。構造化引用8 URLはseen完全一致0だったが、二次情報・解説や新着に不適切な候補を含み、本文の発表日にも疑義がある。**URL未記録8件は、検証済みの新規ニュース8件を意味しない。**

検索が1回でも、検索文脈等によって入力トークンは多くなり得る。`max_tokens` は出力の上限で、入力・検索回数・費用の完全な上限ではない。Chatの無料Web検索枠をAPIの無償保証とせず、アカウント全体の使用量・プラン・有効期限は実行前に確認する。新方式の実測値はまだなく、本番収集への採用は保留する。

## ローカル確認とCI

APIキーなし・ネットワークなしで確認できる。

```sh
python scripts/plamo_probe.py --topic coding --output-dir work/plamo-probe
python -m unittest discover -s tests -p test_plamo_probe.py -v
python -m unittest discover -s tests
```

`--live` は実API送信の明示指定であり、開発・CIでは使わない。出力先はリポジトリ内なら `work/` 以下だけを認め、`logs/`・`data/`・Pagesへ書かない。既存データは照合用の読み取りだけで、収集・再生成・commitは起動しない。

既存CIの恒久設定は `main` のpushとPRが対象。unit/固定品質チェック/Chromium E2Eを実行し、PLaMoの実APIは呼ばない（[初回導入時の事前CI記録](https://github.com/YanTKYS/ai-watch/actions/runs/40528304244)）。検証ワークフロー自体は `workflow_dispatch` だけで、マージとAPI検証はオーナーに委ねる。
