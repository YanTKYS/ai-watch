# 収集状況とデータ鮮度（F04）

`data/collection-status.json` は公式フィード収集と検索インデックス生成の公開用スナップショット。記事の最新日付とは別に、**最後に公開された試行結果**をPagesで確認する。現在のジョブの稼働監視や通知ではなく、Braveの利用状況も含めない。

## 収集と生成を分けて記録する

通常の `python scripts/collect.py` は開始時と公式フィード処理完了時に状態を保存する。

- `attempted_at`: 実際に収集処理へ入った時刻。JSTオフセット付きISO 8601。記事の取得日指定から時刻を推定しない。
- `completed_at`: その公式フィード処理が終了した時刻。開始だけならnull。
- `last_all_success_at`: 設定された全フィードの取得・解析とログ/履歴/月一覧の処理が成功した最後の時刻。部分/全失敗・保存エラーでは前回値を維持。未知の過去時刻はnull。
- `result`: success / partial / failed / running / error / unknown。
- `feeds`: フィード名と取得・解析のsuccess/failed、選定前の候補数、採用カード数。候補数は期間・必須語・履歴等の除外後。複数リリースの集約後は採用1件。取得失敗時の件数はnullで、正常0件と区別する。
- `new_articles`: 今回採用してログ処理まで完了したカード数。処理未完了はnull。記事0件でも試行時刻を更新する。
- `run_key`: Actionsの公開実行番号と再実行番号。前回の状態を今回の実行結果と誤認しないための関連付けで、認証情報ではない。ローカルではnull。

HTTPエラー・XML不正等はフィード別のfailedとなり、残るフィードは処理する。全フィード失敗はBraveが成功しても終了コード1。状態保存ができない場合も非0終了にする。設定・履歴不正は従来の2、記事保存等の例外も成功へ変換しない。公式フィードの完了後にBraveだけが失敗した場合、公式フィードの成功を失敗へ書き換えない。

状態の書き込みは一時ファイルからの置換。公開するのは既知の固定フィールドだけで、レスポンス本文、記事タイトル/URL、診断情報、例外メッセージ、検索結果、秘密値は含めない。`--dry-run` / 品質評価はこの保存経路を呼ばない。

## Actionsでの記録と配信の境界

収集Actionsは次の順番で実行する。

1. **Collect**: 記事・履歴・月一覧と収集状態を記録。失敗を `continue-on-error` で隠さない。
2. **Update search index**: 従来どおり失敗しても後続を実行。既存インデックスは生成失敗で消さない。
3. **Record collection and index status**: `steps.collect.outcome` / `steps.search_index.outcome` を渡して記録。`conclusion` は使わない（continue-on-error後のsuccessと混同するため）。
4. **Commit and push**: 記事・既存dataと `data/collection-status.json` を差分保存。

後続3ステップは `!cancelled()` なので、収集の非0終了後も可能な範囲で記録・commitを行う。収集ステップの失敗があれば、後続が成功してもジョブ自体は失敗のまま。キャンセル・強制終了では後続が動くとは保証しない。

インデックスにはchecked_at、success/failed/skipped、last_success_at、対応する収集のattempted_atを記録する。生成失敗でも過去の生成成功日時は保つ。新しい収集と対応しない古い生成結果は「今回の生成は未確認」と表示する。収集処理が今回始まらなかった場合は試行日時をnullとし、後続の状態記録時刻を収集開始時刻として捏造しない。

生成成功は、**生成時点の事実**だけを表す。後続のcommit/push失敗・Pages配信遅延では、ブラウザへ新状態が届かない。Actions自体の未起動もJSONでは直接観測できない。画面は最後に届いた試行時刻の古さで「更新遅延」を示すが、停止・Git失敗・配信失敗のどれかは断定しない。

## 画面の判定

| 観測結果 | 表示 |
| --- | --- |
| 全フィード成功・採用あり | 正常・新着N件 |
| 全フィード成功・採用0件 | 正常・新着なし |
| 一部フィード失敗 | 一部取得失敗（0件でも正常な新着なしとは言わない） |
| 全フィード失敗 | 取得失敗 |
| 保存エラー等で未完了 | 取得失敗（収集処理未完了） |
| 開始記録だけで未完了 | 状態不明（収集未完了） |
| 最終試行が36時間超前 | 更新遅延、前回の結果と時刻を併記 |
| 状態なし・旧形式・破損・404・通信失敗・大きく未来の時刻 | 状態不明。記事の閲覧を維持 |

遅延しきい値は `collection-status.js` の `STALE_HOURS = 36`。毎日JST 06:41の24時間間隔に、Actions遅延への12時間の猶予を取った初期値。開始予定時刻に実行が保証されるという意味ではなく、運用に合わせて変更する。

取得は表示時の1回だけ。取得後はキャッシュした時刻を1分ごとに閲覧時刻と比較し、タブを開き続けても古い正常をいつまでも正常と見せない。表示中の記録が古い場合は再読み込みを案内する（サーバーの最新状態を定期取得しているわけではない）。時刻表示はJST。役割status/aria-live=politeの独立した領域に表示し、同じ文言は更新しない。フィード別内訳はキーボードで開けるdetailsに置く。

状態の取得は日刊・検索と別で、F05のエラーや再試行操作を上書きしない。`?sample` では領域を隠し、本番状態も取得しない。

## 状態の例（合成、2フィードへ簡略化）

```json
{
  "schema_version": 1,
  "collection": {
    "attempted_at": "2026-10-24T08:00:00+09:00",
    "completed_at": "2026-10-24T08:01:00+09:00",
    "last_all_success_at": "2026-10-23T08:01:00+09:00",
    "result": "partial",
    "new_articles": 0,
    "feeds": [
      {"name": "Feed A", "status": "success", "candidates": 0, "adopted": 0},
      {"name": "Feed B", "status": "failed", "candidates": null, "adopted": null}
    ],
    "run_key": "123:1"
  },
  "index": {
    "checked_at": "2026-10-24T08:02:00+09:00",
    "result": "failed",
    "last_success_at": "2026-10-23T08:02:00+09:00",
    "for_collection": "2026-10-24T08:00:00+09:00"
  }
}
```

この例は新着なしではなく一部取得失敗で、検索生成も失敗。双方の前回成功時刻は残る。36時間を超えて閲覧すれば更新遅延となる。実運用では設定された7フィードを記録する。

初期の追跡ファイルは `collection: null, index: null`。既存ログ・Actions履歴から成功時刻を埋め戻さない。マージ/初回配信直後は状態不明で、次の実際の収集・生成・commit/配信を経て初めて観測結果が表示される。このPRで実フィード収集を行って過去データを更新することはしない。

## 検証

`python -m unittest discover -s tests -v` で収集状態の永続化、部分/全失敗、前回成功維持、保存エラー、Actionsの対応付け・順序・commit対象、dry-runの非書き込み、Node上の時刻判定・表示・通信失敗・sample分離を検証する。既存の選定・Brave・インデックス・再試行テストも継続する。
