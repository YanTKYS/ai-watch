| URL | https://github.com/QwenLM/Qwen3-VL |

| ライセンス | Apache-2.0 |
| 主なモデル | 2B / 4B / 8B / 32B（通常型）、30B-A3B・235B-A22B（MoE型）。それぞれInstruct版とThinking版、FP8版あり |

**概要**: 画像・動画・文書を読み取れるマルチモーダルモデルです。OCRは32言語に対応し、暗い・ぼやけた・傾いた画像や、難しい漢字・専門用語にも強くなったとされます。長い文書のレイアウト解析も改善されています（[README](https://github.com/QwenLM/Qwen3-VL)）。文書解析、OCRと項目抽出、長文書の理解などの実装例（cookbook）も公開されています（[cookbooks](https://github.com/QwenLM/Qwen3-VL/tree/main/cookbooks)）。

**自治体業務への応用**
- 帳票処理: 紙の申請書・届出書をスキャンし、「氏名・住所・申請日」などの項目をJSONで取り出す処理を、閉域サーバーで試作できます。AI-OCRサービスへの外部送信が難しい帳票の代替候補になります。
- 文書管理: 過去の紙文書をPDF化した資料からレイアウトを保ったままテキストを抽出し、前回までに紹介したRAGFlowやxerjの検索対象にできます。
- 注意点: 日本語の手書き文字や旧字体の精度は、実際の帳票で検証する必要があります。抽出結果は必ず職員が確認する運用（人による最終確認）を前提にしてください。

### 2. NVIDIA/auto-ontology — 庁内データベースへの自然言語問い合わせ基盤

| 項目 | 内容 |
| --- | --- |
| URL | https://github.com/NVIDIA/auto-ontology |
| 今週のスター / 総数 | +5,802 / 約12,200（Python部門トレンド） |
| ライセンス | Apache-2.0 |
| 動作要件 | Docker ComposeまたはKubernetes（Helm）、Python 3.12以上、Postgres。推論はNVIDIA NIM（クラウド版またはセルフホスト版）か、OpenAI互換のAPI |

**概要**: 複数のデータベースのメタデータから「どの表に何があり、どの定義が正しいか」という意味の層（オントロジー）を自動で作ります。自然言語の質問をSQLに変換して実行し、回答には根拠（どのデータ・定義を使ったか）を付けます。MCP・CLI・API経由で、各種AIエージェントから使えます。ログインと権限管理（RBAC）も備えています（[README](https://github.com/NVIDIA/auto-ontology)）。

**自治体業務への応用**
- 住民基本台帳・税・福祉などの統計用データ（個人を特定できないよう加工した集計データ）に対し、「地区別の高齢化率の推移は？」と自然言語で聞ける、政策立案向けの分析基盤として検討できます。
- 部署ごとに違う項目の定義（例: 「世帯」の数え方）を突き合わせる機能は、EBPM（根拠に基づく政策立案）のデータ整備に役立ちます。
- 注意点: 既定の設定はNVIDIAのクラウド推論を使います。閉域で使う場合は、`.env` で推論先を庁内のOpenAI互換サーバー（ollama・llama.cppなど）に変える必要があります。個人情報を含む原データには直接接続しないでください。

5. 独立した再検証

**自治体業務への応用**
