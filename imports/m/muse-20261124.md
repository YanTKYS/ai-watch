## 1. エージェントの定例仕事は、「時間と出来事で呼ぶ」型にする

- 分野: 開発・業務自動化
- 何を楽にするのか: 毎朝の集計や週次の点検のように、決まった時刻や出来事が起きたときにだけ回したい仕事を、人が毎回呼び出す手間から解放する。
- 再現の仕組み: OpenCode 2.4.0（2026-11-23公開）の Automations の型を参考にする。プロンプト・スクリプト・シェルコマンドのいずれかを、1回だけ・一定間隔・cron・MCPサーバーからのイベントのいずれかで走らせる。`/automation` コマンドで管理し、シェル実行は作るときに1回だけ承認を通し、実行ごとの終了コードと出力を記録する。Code Mode のプログラムに「送るかどうか」の判断を任せることもできる。運用の型としては、定例の仕事を「いつ・何をきっかけに・何を実行するか」の3点で書き、承認が必要な段は作るときに決めておく。なお Automations は実験的な機能で、`automations` フラグの有効化が必要。あわせて追加された内蔵デスクトップブラウザは、Chrome・Edge・Firefox・Safari からサインインと履歴を取り込み、エージェントが同じページをサインイン済みで読んで操作できる。
- 何が新しくなったか: エージェントが「呼ばれたら動く」形から、「時刻と出来事で自分から動く」形へ進んだ。MCP の出来事をきっかけにする点では 2026-11-19 にベータ入りした MCP Events と同じ流れだが、こちらは特定のエージェント製品の中で定例化まで一気通貫で回せる。
- 出典リンク: https://opencode.ai/changelog?area=core,sdk,desktop

## 2. 複雑な調査は、「モデルの違うエージェント同士に点検させる」型にする

- 分野: 調査・分析
- 何を楽にするのか: 決算書の読み込みや取引先のデューデリジェンスのように、1つのモデルに任せると見落としや思い込みが残りやすい大きな調査で、別々の視点からの点検を組み込む。
- 再現の仕組み: Perplexity Computer の Multiagent（2026-11-17発表、Ultra の上の努力レベル）の型を参考にする。リードエージェントが仕事を分け、最大16人のエージェントが異なるフロンティアモデルで並行して調べ、見つけた内容を直接やり取りし、互いの仕事を点検してからリードが1つの答えにまとめる。既定の編成は、計画役の Claude Fable 5.2 が、Claude Opus 5.5・GPT 6.1 Sol・Gemini 4 Carbon を走らせるエージェントに割り振る。運用の型としては、調査を始める前に「分けて並行できる部分」と「点検してほしい観点」を決め、最後は人が根拠と結論の対応を確認する段を残す。対象として Perplexity が挙げるのは、複数シナリオの財務予測、年次報告書の点検、取引のデータルーム調査、複雑な税務申告と年末調整、競合する説明の深掘り。
- 何が新しくなったか: エージェントのチームが「別々のモデルで動く」ことが製品の機能になった。同じモデルを増やすのではなく、違うベンダーのモデル同士が証拠を渡し合い、前提に異議を唱える形で点検する。なお Perplexity は精度や速度のベンチマークを公表しておらず、クレジット消費が大きいとも述べており、最も重要な仕事向けと位置づけている。利用は Perplexity Max 契約者でウェブのみ。
- 出典リンク: https://www.perplexity.ai/hub/blog/introducing-computer-multiagent

## 3. AIへの伝え直しは、「アプリをまたいで覚える記憶」に任せる型にする

- 分野: 業務全般
- 何を楽にするのか: Word で好みの書式、Outlook でメールの口調、Teams で話し方と、アプリごとに同じ好みを何度も伝え直す手間を減らす。
- 再現の仕組み: Microsoft 365 Copilot の Work IQ の記憶（2026-11-18、Ignite 2026で発表）の型を参考にする。4つの更新がある。Word・Excel・PowerPoint・Workspaces・Pages・Outlook・Teams をまたいで、書式・口調・構成の好みを Copilot が学ぶ（一般提供へ展開中）。回答に記憶が使われたときは、出典から「個人設定」タブを開いて、どの指示・保存した記憶・過去のチャットが効いたかを確認でき、不要な記憶はそこから削除できる（一般提供済み）。メールの文面では、相手ごとに変える口調や構成も学ぶ（一般提供へ展開中）。Work IQ MCP を通じて、承認された自作のエージェントやアプリも同じ記憶プロファイルを読める（一般提供へ展開中）。運用の型としては、記憶に残してよい好みと残してはいけない情報を先に決め、定期的に「個人設定」タブで記憶の一覧を確認する。管理者はテナント全体または Entra グループ単位で個人設定を切ることもできる。
- 何が新しくなったか: Copilot の記憶が「チャットの中だけ」から「Microsoft 365 のアプリ全体」へ広がり、しかも何を根拠にしたかが確認できるようになった。記憶が「ブラックボックスの好み」から「点検できる一覧」へ変わった点が、業務で使ううえでの進展になる。
- 出典リンク: https://techcommunity.microsoft.com/blog/microsoft-copilot-blog/the-end-of-starting-over-how-work-iq-helps-copilot-understand-you-and-your-work/4571169

## 4. 個人とチームのタスクは、「エージェントも読む1つの計画表」に集約する型にする

- 分野: タスク管理
- 何を楽にするのか: 個人の To Do、チームの Planner、プロジェクトの Premium 計画と、タスクが3つの場所に分かれていて、エージェントがどれを見ればいいか分からない状態をなくす。
- 再現の仕組み: Microsoft の unified plans（2026-11-18発表）の型を参考にする。To Do と Planner の基本・Premium 計画を1つの基盤に集約し、Outlook・Teams・Planner・Loop から同じ計画表を使い、Copilot と Cowork からも利用できる。Planner MCP サーバーが Work IQ の一部として計画と実行をつなぎ、自作のエージェントも計画を読める。運用の型としては、個人のタスク・チームの計画・組織の計画を同じ表に置き、「誰が・いつまでに・どの状態か」を1つの形で残す。ライセンスごとの機能差（Goals 表示や Timeline 表示など Premium 機能）は、Copilot・Planner Plan 1・Planner and Project Plan 3 のどれを持っているかで決まるため、チームで使う機能を先に決めておく。なお Microsoft は To Do アプリを 2027-06-30 に終了すると発表しており、既存の To Do タスクはそれまで Planner 経由で見られるが、新しい個人用プランへ自動移行はされない。個人用 Microsoft アカウントには Planner の代替は用意されないため、個人で To Do を使っている場合は他のタスク管理アプリへの移行とエクスポートの準備が必要になる。
- 何が新しくなったか: タスク管理が「人が使う場所」と「エージェントが読む場所」に分かれていた状態から、1つの基盤でつながる形へ進んだ。Copilot・Cowork・Autopilot が同じ計画表を読む前提が整った。
- 出典リンク: https://techcommunity.microsoft.com/blog/plannerblog/introducing-unified-tasks-and-plans-for-copilot-and-microsoft-365/4573958

## 5. エージェントの仕事は、「誰が・誰のためか」を履歴に残す型にする

- 分野: チーム協働・ガバナンス
- 何を楽にするのか: ページの編集やコメントが「誰が書いたのか分からない」状態になり、後から確認するときに人とエージェントの仕事が区別できない問題を減らす。
- 再現の仕組み: Confluence Cloud のエージェント帰属表示（2026-11-17から展開）の型を参考にする。エージェントがページ・ライブドキュメント・ブログ・ホワイトボード・データベースで作る・見る・編集する・コメントするとき、誰が・誰のために動いたかが表示される。人のために動いた場合は「エージェント名 with 人名」の両名表示になり、自動化のように独りで動いた場合はエージェント名だけになる。表示される場所は、投稿者と版の履歴、分析、コメント、通知、閲覧中のアバター、監査ログ。対象は Rovo、Atlassian Studio のエージェント、Forge のエージェント、MCP v2 で登録された外部のエージェント（Claude・Cursor・ChatGPT など）。MCP v1 や Teamwork Graph CLI 経由のものは「外部エージェント」と表示される。運用の型としては、見直しのときに版の履歴と投稿者一覧で「エージェントが触ったページ」と「誰が頼んだか」を確認する段を入れる。なお Atlassian はこれをコンプライアンス用の監査道具ではないとしており、正式な監査には Atlassian Guard を使う。
- 何が新しくなったか: エージェントの参加が「裏で動いているもの」から「履歴に名前が残るもの」へ変わった。版の履歴では人と AI の編集を色分けで区別する表示も追加される予定で、チームの記録として誰が何をしたかが後から追えるようになる。
- 出典リンク: https://support.atlassian.com/confluence-cloud/docs/agentic-attribution-in-confluence/

## 6. プロンプトの上達は、「自分の仕事で練習するコーチ」に任せる型にする

- 分野: 人事・育成
- 何を楽にするのか: 社員が Copilot の使い方を「講座で学ぶだけ」で終わらせ、実際の仕事では毎回ゼロからプロンプトを書く状態を減らす。
- 再現の仕組み: Microsoft 365 Copilot の Learning Agent の新しい4つの体験（2026-11-17発表）の型を参考にする。AI スキル向上タブで、自分の仕事に合った学び方と次に試すことが分かる。AI Skills Navigator の厳選プレイリスト（役割・製品・スキルごとに束ねた講座・動画の組み合わせ）を仕事の流れの中で開ける。Copilot のスタータープロンプトで、実際の仕事を題材に「目標・文脈・情報源・期待する結果」の4点でプロンプトを作る練習ができる。プロンプトコーチングでは、自分の今の仕事から取り出した場面で、目標をはっきりさせ、役立つ文脈と情報源を添え、よい結果がどういうものかを言葉にしてからプロンプトを書く。運用の型としては、研修を「講座を受ける」形から「自分の仕事を題材に1回練習する」形に変え、部署ごとによくある仕事のスタータープロンプトを集めて共有する。Learning Agent は Microsoft 365 管理センターの「エージェント」ページから有効化する。
- 何が新しくなったか: 学びが「Copilot について知る」段階から「自分の仕事で Copilot と Cowork を使う」段階へ進み、しかも練習の題材が自分の仕事そのものになった。プロンプトの型（目標・文脈・情報源・期待する結果）が、練習を通じて身につく形で用意された。
- 出典リンク: https://techcommunity.microsoft.com/blog/microsoft-copilot-blog/learning-agent-build-ai-and-copilot-skills-through-everyday-work/4573000

## 7. CRMは、「画面を開かずAIから使う」型にする

- 分野: 営業
- 何を楽にするのか: 商談の要約や更新連絡の準備のたびに CRM の画面を開いて探し回る手間を減らし、営業・カスタマーサクセス・マーケティングが普段使っている AI アシスタントの中で CRM を使えるようにする。
- 再現の仕組み: HubSpot のヘッドレス価格（2026-11-17発表）の型を参考にする。Claude・ChatGPT・Gemini・Microsoft Copilot 向けのコネクターと MCP サーバー、Agent CLI を通じて、開いている商談の要約、更新連絡の準備、キャンペーンの立ち上げなどを AI アシスタントの中で行う。課金の型は3通りで、日常的なコネクター利用は席に含まれ追加料金なし。自作や他社製のエージェントを既存の API につなぐ場合は、そのプランに含まれる API 容量の範囲で使い、クレジットは消費しない。統制・追跡・専用道具を備えた管理環境でエージェントを大規模に動かす場合は HubSpot クレジットで支払う。運用の型としては、まず「席に含まれる日常利用」と「API 容量で回す自作エージェント」と「クレジットで払う大規模な自動化」の3つに分け、どの仕事がどこに入るかを決めてから接続する。なお、日常利用の上限やクレジット環境の価格・開始時期は未発表のため、導入前に確認する。Claude 側は有料プラン（Pro・Max・Team・Enterprise）が必要。
- 何が新しくなったか: CRM が「画面で開くもの」から「AI アシスタントから使うもの」へ変わり、その境目が料金の型として示された。日常利用は席に含まれる一方で、大規模な自動化は別枠の課金になるため、どこまでを「日常」とするかの線引きが先に決められるようになった。
- 出典リンク: https://www.hubspot.com/company-news/pricing-headless

## 8. 管理者の定型対応は、「権限のままに動く管理スキル」に任せる型にする

- 分野: IT運用
- 何を楽にするのか: 「この課題が開けない」「使われていないトークンがないか」といった管理者の問い合わせ対応で、設定画面を1つずつ開いて調べる手間を減らす。
- 再現の仕組み: Atlassian Administration の Rovo Chat と管理スキル（2026-11-17時点のベータ）の型を参考にする。管理画面で Rovo Chat を有効化すると、上部の「Ask Rovo」から管理スキルを `/` で呼び出せる。スキルの例は、ユーザーの招待とグループ追加、Jira の課題が見られない理由の調査、180日使われていない API トークンの一覧、空のグループや最近活動のないユーザーの洗い出し、SCIM プロビジョニングと SAML シングルサインオンの設定手順の案内。スキルは管理者本人の権限の範囲で動き、変更を伴う操作は確認を求めるものもある。運用の型としては、よくある管理対応をスキル名で一覧にし、「Rovo に聞く」ことを一次対応の手順に入れる。なおベータの対象は、有料アプリを1つ以上持ち、有料席が100席超の組織で、Standard・Premium・Enterprise プラン。Jira や Confluence の中で設定された権限までは見えない場合があり、古い API トークンの一括削除はできないという制限もある。
- 何が新しくなったか: 管理作業が「設定画面を開いて調べる」形から、「エージェントに聞いて権限の範囲で動かす」形へ進んだ。管理スキルが管理者の権限をそのまま使うため、権限を広げずに定型対応を任せられる。
- 出典リンク: https://support.atlassian.com/organization-administration/docs/use-rovo-chat-and-admin-skills-in-your-organiztion/

## 9. 繰り返しの仕事は、「手順書ファイルとしてCopilotに載せる」型にする

- 分野: 業務全般
- 何を楽にするのか: 毎週の報告書や定例の集計のように、同じ指示をチャットに毎回貼り直す手間と、人によって手順がばらつく問題を減らす。
- 再現の仕組み: Microsoft 365 Copilot Chat のスキル（2026年11月に一般提供）の型を参考にする。繰り返す仕事の手順を `SKILL.md` ファイルに書き、必要なら参考ファイルやスクリプトを添えてスキルとして保存する。Copilot は依頼に合うスキルを自動で選ぶか、ユーザーが明示的に選んで使う。スキルの説明文が自動選択の決め手になるため、説明文には「どんな仕事に使うか」を具体的に書く。`SKILL.md` は2万字以内を目安にし、細かい内容は添付ファイルに分ける。スクリプト（Python・JavaScript・TypeScript・シェルなど）はネットワークなしの隔離環境で動き、外部への呼び出しはできない。個人のスキルはチャットから作るかアップロードし、組織で配るスキルはプラグインとして配布する。運用の型としては、部署で回数の多い仕事から3〜4件だけスキル化し、使う前に小さなグループで試してから広げる。スキルの中身は共有相手に読まれるため、秘密情報を入れない。管理者はテナントで特定のスキルをブロック・制限できる。
- 何が新しくなったか: これまでエージェントを作らないと残せなかった「仕事の手順」が、チャットの中で作れるスキルの形で残せるようになった。2026-11-20に取り上げた Dynamics 365 の100超の既製スキルが「業務アプリ側の定型操作」だったのに対し、こちらは「自分のチームの繰り返し仕事」を自分でスキル化する型になる。
- 出典リンク: https://learn.microsoft.com/cs-cz/microsoft-365/copilot/extensibility/whats-new
