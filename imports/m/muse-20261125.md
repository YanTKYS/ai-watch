## 1. デザイン制作は、「編集できる成果物をエージェントに作らせる」型にする

- 分野: 資料作成・デザイン
- 何を楽にするのか: 営業資料やSNS用の画像、プレゼン資料を作るたびに、AIに画像を出させてからデザインアプリで作り直す二度手間を減らす。
- 再現の仕組み: Canva の MCP サーバー（2026-11-23発表、一般提供）の型を参考にする。ウェイトリストがなくなり、Canva Developer Portal で登録して MCP アクセスを有効化すれば、ChatGPT・Claude・Gemini・Muse などのエージェントから Canva を呼べる。エージェントが出すのは平らな画像ではなく、編集できる Canva のデザイン・画像・動画で、背景削除・リサイズ・エクスポートも行える。あわせて新しい REST API、拡張された CLI、サービスアカウントが加わり、Canva Craft も MCP・API 経由で使える。運用の型としては、ブランドの色・書体・ロゴを Canva 側のブランドキットに固定し、エージェントには「何を作るか」だけを渡して、出来上がりは編集できるファイルのまま人が確認する。Canva によれば、10月だけで MCP 経由の利用が前月比93%増え、MCP 経由の新規登録は約50万人にのぼる。
- 何が新しくなったか: エージェントの制作物が「使い捨ての画像」から「あとから直せる編集ファイル」へ変わった。デザインの型が Canva 側に残るため、作り直しではなく手直しで済む。
- 出典リンク: https://www.financialexpress.com/life/technology/canva-makes-mcp-generally-available-to-developers-what-it-means-for-you/4392768/

## 2. プルリクエストは、「レビュー・修正・承認を方針ファイルで回す」型にする

- 分野: 開発
- 何を楽にするのか: コードを書いたあと、レビュー指摘への対応、CI の失敗直し、マージ待ちの承認と、プルリクエストを開いてからの作業で開発者が何度も手を止められる状態を減らす。
- 再現の仕組み: Anthropic の Claude Ship（2026-11-23発表、ベータ）の型を参考にする。3つの仕組みが順に動く。Code Review（一般提供済み）が Quick・Standard・Deep の深さでレビューし、指摘を検証して分類して投稿する。PR Steward（ベータ）が CI の失敗、マージの衝突、レビューへの指摘に対応してプルリクエストを緑の状態に保つ。Claude Approvals（ベータ）が、リポジトリに置いた承認の方針ファイル（`.claude/approvals.yml`）を読み、人の承認が要る変更か、Claude が承認してよい変更かを決める。個人は Claude Code の `/ship` コマンドで、リポジトリ単位では管理者が有効化して使う。料金はトークン量に応じた従量課金。運用の型としては、承認の方針を「どの変更なら自動承認してよいか」というファイルとしてチームで決め、最初は観察のみのモードで動かして判断を確認してから承認を任せる。Anthropic 自身の Claude Code チームでは、6月から9月にかけてマージされたプルリクエストが2倍超になり、差し戻しの割合が40%超減ったとされる。対象は Claude の Team・Enterprise プランで、GitHub のリポジトリ。
- 何が新しくなったか: コード生成のあとに残っていた「レビューから承認まで」の工程が、方針ファイルというチームの資産として残せる形で自動化された。承認の判断基準が設定画面ではなく、リポジトリの中のファイルになる。
- 出典リンク: https://claude.com/ja/resources/articles/introducing-claude-ship

## 3. スキルと接続は、「プラグイン1つに束ねて配る」型にする

- 分野: 業務全般・ガバナンス
- 何を楽にするのか: スキル・コネクター・プラグインが別々の画面に散らばり、チームで「何を入れてよいか」が分からなくなる状態をなくす。
- 再現の仕組み: Claude の Plugins ページへの統合（2026-11-23に案内）の型を参考にする。サイドバーの「Customize」が「Plugins」になり、スキル・コネクター・プラグインを1つの画面で探し・追加・管理する。プラグインはスキル・コネクター・スラッシュコマンド・サブエージェントを1つの配布単位に束ねたもので、チームの定型仕事を1つのかたまりとして配れる。Free・Pro・Max・Ultra・Team プランでは10月29日から展開され11月9日に一般提供、Enterprise は11月30日から既定で有効になる。運用の型としては、チームで使う定型をプラグインとしてまとめ、入れるもの・入れないものを一覧で決めてから配る。管理者は11月30日までに組織の Skills 設定を確認する。Skills を無効にしている組織では、そのままでは11月30日以降、Claude Desktop でプラグインが動かなくなるため、使い続ける場合は Skills を有効化する必要がある。なお、プラグインを外してもコネクターの接続は残るため、切るときは別途切断する。
- 何が新しくなったか: チームの仕事の型が「ばらばらの設定」から「プラグインという1つの配布単位」へまとまり、管理の画面も1つになった。導入の可否が11月30日という期限付きの管理作業として示された。
- 出典リンク: https://support.claude.com/en/articles/17740565-manage-plugins-skills-and-connectors-from-one-plugins-page

## 4. 脆弱性対応は、「パッチを待つ間は署名付きの盾で守る」型にする

- 分野: セキュリティ・IT運用
- 何を楽にするのか: 脆弱性が見つかってから正式なパッチが出るまでの間、サービスを止めるか、攻撃を受け入れるかの二択しかなかった状態を減らす。
- 再現の仕組み: OpenAI と Cisco が共同公開した Shirudo（2026-11-23公開、プレリリース）の型を参考にする。Linux の eBPF 技術で動くオープンソースのランタイムで、エージェントが脆弱性の情報を受け取り、狙われた動作だけを止める小さな防御（シールド）を書く。シールドは署名付きの `.bee` パッケージとして配られ、TPM（ハードウェアの信頼の土台）で署名を確認してから読み込まれる。運用の型としては、まずシールドが正規の動きを邪魔しないかを試し、運用者の承認があってから有効化し、正式なパッチが出たらシールドを外す、という3段で回す。実演では、Codex が作ったシールドが Java4Shell 型の攻撃を止めながら、対象のサービスは止めずに動かし続けたとされる。Isovalent の Tetragon を、エージェントが扱える形に書き直したもの。なおプレリリース段階で本番利用はまだ想定されておらず、特定のカーネル機能と TPM 2.0 が必要。
- 何が新しくなったか: 脆弱性への応急対応が「設定を変える」形から「エージェントがコードで盾を書く」形へ変わり、しかも署名と TPM で「何が入っているか」を確かめられるようになった。パッチ待ちの時間を、サービスを止めずに稼げる。
- 出典リンク: https://thehackernews.com/2026/11/openai-and-cisco-unveil-ai-assisted.html

## 5. 難しい文書は、「やさしい言葉と絵への直しはAI、承認は人」型にする

- 分野: 文書作成・アクセシビリティ
- 何を楽にするのか: 病院の案内や銀行の手続き、行政の通知のように、難しい文書を「やさしい日本語（イージーリード）」に直す作業が、1ページ作るのに数日〜数週間かかり、追いつかない状態を減らす。
- 再現の仕組み: Google DeepMind と Mencap の Easy Read Co-Creator Tool（2026-11-19発表、11月24日に DeepMind が改めて紹介）の型を参考にする。Gemini が複雑な文書を短い文と分かりやすい画像に直し、数分で下書きを作る。学習障害のある人々と共に作られ、人の専門家がすべてのページを確認・編集・承認してから出す。運用の型としては、原文・やさしい版・画像の3点を1セットとして残し、公開前の人の承認を必須の段にする。対象は情報を出す組織で、個人向けの公開アプリではない。Google.org が100万ドルを出し、2027年から2030年にかけて50超の組織へ使い方の研修と導入支援を行うとされる。アップロードした内容は保存されず、学習にも使われないとされる。
- 何が新しくなったか: やさしい文書づくりが「人が一から書く」形から「AI が下書きを作り、人が仕上げる」形へ変わり、数週間かかっていた作業が数分で下書きまで進むようになった。ただし作り方の基準と承認は人の側に残る。
- 出典リンク: https://www.learningdisabilitytoday.co.uk/news/mencap-launches-new-ai-easy-read-tool-to-make-information-more-accessible/

## 6. 機密ファイルの分類は、「見分け方を指示文で残し試してから配る」型にする

- 分野: 法務・情報管理
- 何を楽にするのか: 共有ドライブに増え続けるファイルのうち、どれが機密かを人が1つずつ見分けてラベルを貼る手間と、貼り忘れによる漏れを減らす。
- 再現の仕組み: Google Drive の Gemini による AI 分類（2026-11-17に一般提供）の型を参考にする。管理者が「この種類のファイルにはこのラベル」といった見分け方を自然言語の指示文として書き、Gemini がファイルに分類ラベルを付ける。展開する前に、管理コンソールで指示文を試して、どのラベルが付くかを先に確認できる。展開後は、ラベル付けの件数をほぼリアルタイムの報告で見られる。運用の型としては、見分け方の指示文を1つの文書として残し、試して直してから展開し、貼られたラベルを既存の情報漏洩防止（DLP）の管理にそのままつなげる。対象のファイルは共有ドライブ内か、対応ライセンスを持つユーザーが所有するもの。1つの組織で有効にできる Gemini の指示モデルは1つで、AI 分類モデルは合計5つまで。対象は Enterprise Plus・Frontline Plus・Google AI Pro for Education。展開は11月17日から始まり、12月15日までの完了が見込まれる。
- 何が新しくなったか: 機密の見分けが「人が1件ずつ判断する」形から「指示文として残し、試してから一斉に配る」形へ変わった。分類の基準が、人の頭の中ではなく、試せる指示文として残る。
- 出典リンク: https://workspaceupdates.googleblog.com/2026/11/gemini-powered-data-classification-in-Google-Drive-is-now-generally-available.html

## 7. チームの決まりは、「スキルとして保存し@で呼ぶ」型にする

- 分野: 業務全般
- 何を楽にするのか: 文書の書式やメールの口調、報告書の型のように、チームの決まりを毎回チャットに貼り直す手間と、人によって出来がばらつく問題を減らす。
- 再現の仕組み: Google Workspace のスキル（2026-11-10に案内、11月9日から Rapid Release で展開開始）の型を参考にする。チームの決まり・テンプレート・参考ファイルを、再利用できる指示（スキル）として保存する。Workspace Studio や Google ドキュメントで作り・試し・共有し、Gmail・ドキュメント・スライド・ドライブ・チャットの中では、Gemini が合うスキルを自動で選ぶか、@で明示的に呼んで使う。複数のスキルを1つの依頼で組み合わせることもでき、Workspace Studio のフローとつなげることもできる。スキルはオープンな SKILL.md 形式で書かれ、参考ファイルも添えられる。運用の型としては、回数の多い仕事から3〜4件だけスキル化し、共有する前に小さなグループで試してから広げる。スキルの中身は共有相手に読まれるため、秘密情報を入れない。なお Workspace のスキルは Gemini アプリのスキルとは別物で、自動では同期されない。スプレッドシートと Meet ではまだ使えず、英語の指示のみの対応。Scheduled Release は11月30日から展開開始。
- 何が新しくなったか: 前日に紹介した Copilot Chat のスキルと同型の仕組みが、Google Workspace 側でも一般提供に入った。チームの決まりが、チャットの中の指示ではなく、共有して呼び出せるスキルの形で残せるようになった。
- 出典リンク: http://workspaceupdates.googleblog.com/2026/11/skills-in-workspace.html

## 8. 録画資産は、「ブランドの型に沿った完成動画へ直す」型にする

- 分野: マーケティング
- 何を楽にするのか: 撮りためた会議やイベント、製品説明の録画が倉庫に眠り、マーケティング動画や営業資料、研修動画にするたびに編集を一からやり直す手間を減らす。
- 再現の仕組み: OpenReel AI（2026-11-24発表、提供開始）の型を参考にする。OpenReel の中に組み込まれた AI エージェントが、既にある録画素材から、ブランドに沿った完成動画を編集・作成する。対象はマーケティング動画、顧客事例、教育コンテンツ、営業資料。運用の型としては、ブランドの色・書体・表現の基準と、動画の型（長さ・構成・字幕の有無）を先に決めておき、エージェントには素材と用途だけを渡して、出来上がりは人が確認してから公開する。なお詳細はベンダーの発表資料によるもので、料金や利用条件は OpenReel の案内を確認する。
- 何が新しくなったか: 録画の活用が「編集者が一から切ってつなぐ」形から「素材とブランドの型を渡すと完成動画まで進む」形へ変わった。撮りためた資産が、作り直しではなく再利用の材料になる。
- 出典リンク: https://www.globenewswire.com/news-release/2026/11/24/3409293/0/en/openreel-launches-openreel-ai-to-turn-existing-recordings-into-finished-on-brand-video.html

## 9. ブラウザの定型操作は、「開発環境からの言葉で回す」型にする

- 分野: 開発・調査
- 何を楽にするのか: ウェブの画面を開いてボタンを押し、フォームに入力し、情報を抜き出す定型操作を、ブラウザと開発環境の間で何度も往復する手間を減らす。
- 再現の仕組み: GitHub Copilot のブラウザ自動化（Microsoft Ignite 2026で発表、公開プレビュー）の型を参考にする。Chrome 拡張機能（Chrome・Edge に対応）を入れると、Copilot に言葉で頼んで、ページを開く・ボタンを押す・フォームに入力する・情報を抜き出す、といった操作を任せられる。Copilot CLI、Copilot アプリ、Visual Studio Code、JetBrains の各環境から使える。運用の型としては、操作の手順を「開く・押す・入れる・抜き出す」の段に分けて言葉で残し、人の確認が要る段（送信や購入など）は止める。なおブラウザの操作は既定では無効で、使うには明示的に有効化する必要がある。
- 何が新しくなったか: 開発環境のエージェントが「コードを書く」範囲から「ブラウザを操作する」範囲へ広がり、画面の定型操作も開発の仕事の流れの中で回せるようになった。既定で無効という安全側の初期設定も含めての進展になる。
- 出典リンク: https://windowsreport.com/microsoft-turns-github-copilot-into-an-ai-browser-agent-for-chrome-and-edge/

## 10. 秘密情報の混入は、「エージェントの輪の中で検出する」型にする

- 分野: 開発・セキュリティ
- 何を楽にするのか: エージェントが書いたコードや接続文字列に、API キーやパスワードなどの秘密情報が紛れ込み、プルリクエストを開いてから見つかる状態を減らす。
- 再現の仕組み: GitHub Copilot のオンデマンドのシークレットスキャンと適応型レビュー（2026-11-17提供）の型を参考にする。Copilot の `security-review` が、GitHub の確定的な秘密情報の検出器と、細かく調整された資格情報の検出モデルを組み合わせて、Copilot CLI・Copilot アプリ・SDK のエージェント作業と、プルリクエストのコードレビューの中で動く。検出の対象は、変更・追加された行だけ。あわせてレビュー作業の深さを Lite・Balanced・Max から自動で選ぶ適応型レビュー、公開リポジトリをまたいだ文脈の読み込み、レビューの効果を測る Repository insights が加わった。運用の型としては、秘密情報の検出を「レビューの段」ではなく「エージェントが書いている段」に入れ、検出されたらその場で直す手順にする。なおシークレットスキャンは既定では無効で、ツールやリポジトリごとに明示的に有効化する必要がある。過去のコミット全体ではなく、現在の差分の対象行だけを見る点にも注意する。
- 何が新しくなったか: 秘密情報の検出が「あとから走らせる検査」から「エージェントが作業する輪の中で動く仕組み」へ変わった。検出の基準が、モデルの判断だけでなく確定的な検出器と組み合わさった点も進展になる。
- 出典リンク: https://codebumble.net/insights/github-copilot-secret-scanning-on-demand-agents
