## 1. 大量の判定は、「生成させず確率付きで採点する専用モデル」に任せる型にする

- 分野: 開発・サポート
- 何を楽にするのか: 問い合わせの振り分け、エージェントのツール選択、ポリシーチェック、回答の採点といった「判定」のたびに大きな生成モデルを回すコストと待ち時間を減らす。
- 再現の仕組み: Google の Gemini Decisions API と Gemini Decision 1（2026-11-12発表）の型を参考にする。テキスト・画像・音声・動画・PDFを共有の入力として、最大1,000問の閉集合判定（yes/no、選択、採点）を1回の順伝播で確率付きで返す。出力トークンの課金はなく、入力は100万トークンあたり0.10ドル、対応遅延は150〜250ミリ秒とされる。運用の型としては、判定の問いを「選択肢の集合＋採点基準」として固定し、生成モデルには判断させず、判定モデルが返した確率と閾値で振り分け・承認・差し戻しを決める。Google は Gemini Notebook・Stitch・Google Search など自社製品でも使っているとされる。
- 何が新しくなったか: 判定が「生成モデルに聞く重い仕事」から、「確率付きで返す安く速い専用処理」へ進んだ。エージェントの中のルーティングや採点が、生成コストを払わずに回せるようになった。
- 出典: https://x.com/googledevs/status/2120583940247552381

## 2. クラウドのテスト環境は、「エージェントが書いたローカル模倣品」で回す型にする

- 分野: 開発
- 何を楽にするのか: AWS アカウントなしで、コーディングエージェントがクラウド連携のコードを繰り返しテストできるようにし、クラウド費用とアカウント権限の手間を省く。
- 再現の仕組み: Amazon の AWS Emulator（2026-11-12発表）の型を参考にする。ローカルで AWS サービスをエミュレートするツールで、全コードを数千の自律 AI エージェントが書き、人間はコードを書いたりレビューしたりしていないとされる。開発者やコーディングエージェントが AWS アカウントなしでローカルテストできる。ソースは GitHub で CC0 ライセンスとされる。運用の型としては、エージェントの開発ループに「ローカルの模倣環境でテスト→通ったら本物の環境で確認」という段を固定し、模倣環境の差分はテスト結果と一緒に記録する。
- 何が新しくなったか: エージェントによる大規模コード生成が、実用ツールとして公開される段階に入った。テスト環境そのものをエージェントが作り、エージェントの開発を支える循環ができた。
- 出典: https://x.com/amazon/status/2120575445213347886

## 3. AIの同僚は、「個人のアシスタント」ではなく「チームで共有する隊員」にする型にする

- 分野: 協働・チームワーク
- 何を楽にするのか: 個人ごとにバラバラの AI 活用をやめ、チーム全員が同じ AI の同僚と働けるようにし、引き継ぎと学習をチームの資産にする。
- 再現の仕組み: xAI の Grok Bot 1.0（2026-11-12発表）の型を参考にする。AI チームメイトとしてチーム全体で協働でき、Bot の共有、Slack や Teams での協働、会議への招待ができる。使うほど学習して役立つようになるとされる。運用の型としては、Bot に「チームの決まり・用語・承認の線」を共有の知識として渡し、会議への参加範囲と発言してよい場面をあらかじめ決めておく。個人のアシスタントとして育てたものを、共有の設定として切り出す手順を定型化する。
- 何が新しくなったか: AI アシスタントが「個人の道具」から「チームに所属する同僚」へ進んだ。共有・会議参加・学習が1つの Bot にまとまり、チームでの運用が現実的になった。
- 出典: https://x.com/bot/status/2120582957782200586

## 4. 顧客対応のエージェントは、「再利用スキル＋判断の追跡」で統制する型にする

- 分野: サポート
- 何を楽にするのか: 顧客対応のエージェントを1件ずつ作り直す手間を省き、判断の根拠をあとから確認できる形で、顧客の一連の流れ全体を任せる。
- 再現の仕組み: NiCE の Cognigy 次世代版（2026-11-12発表）の型を参考にする。AI による開発支援、再利用できるスキル、判断の追跡、音声同士の直接対話が加わった。開発環境（Agentic Experience Studio）では音声認識・音声合成・言語モデルがあらかじめ用意され、AI アシストが構築・デバッグ・シミュレーションを手伝う。追跡では、出力の裏にある起動したスキル・ツールとモデルの呼び出し・トークン使用量・最初の応答までの時間・代替手段に回った理由を確認できる。既定のモデルは会話の料金に含まれ、別契約や設定は不要とされ、Deepgram・ElevenLabs・Anthropic などの高機能モデルは従量課金で追加できる。既存の顧客は追加の移行なしに新機能を使えるとされる。
- 何が新しくなったか: 顧客対応 AI が「1件の問い合わせへの自動返信」から、「スキルを使い回し、判断を追跡できる統制付きの同僚」へ進んだ。モデルの契約と課金が会話料金に吸収され、導入の段取りが軽くなった。
- 出典: https://www.unite.ai/nice-upgrades-cognigy-for-governed-enterprise-ai-agents/

## 5. 外部データの調査は、「1つの鍵と1つの接続口」でエージェントに渡す型にする

- 分野: 調査・分析
- 何を楽にするのか: SEC 提出書類・連邦支出・経済指標・判例など、提供元ごとに違う外部データを集める手間をなくし、社内データと分けて安全に扱う。
- 再現の仕組み: Data.co（2026-11-12発表）の型を参考にする。Data.co Control は社内データ源とつなぎ、組織の基盤の中でプライベートな言語モデルを動かし、AI の活動を統制する。オンプレミス・プライベートクラウド・ハイブリッド・完全なエアギャップに対応するとされる。Data.co Marketplace は25の提供元から91のデータセットを集め、1つの API キーでブラウザの問い合わせ画面・REST API・MCP サーバー経由で使える。運用の型としては、外部データの取得口を MCP サーバー1つに集約し、「どのデータセットを・誰が・どれだけ使ったか」を API キー単位で記録する。個人情報を含む社内データは Control 側に残し、外部へは出さない線引きを固定する。
- 何が新しくなったか: 外部データの利用が「提供元ごとの契約と接続」から、「1つの鍵で91のデータセットをエージェントに渡す」形へ進んだ。プライベート AI と外部データの marketplace が同じ土台に載った。
- 出典: https://www.manilatimes.net/2026/11/12/tmt-newswire/plentisoft/dataco-launches-private-ai-platform-and-data-marketplace-featuring-91-datasets-from-25-providers/2468027

## 6. 制作ツールは、「人が開くアプリ」ではなく「エージェントが呼ぶ部品」にする型にする

- 分野: マーケティング・デザイン
- 何を楽にするのか: デザイン制作を、人がアプリを開いて操作する作業から、エージェントが指示で動かす作業へ変え、ブランド基準のばらつきを抑える。
- 再現の仕組み: Adobe MAX 2026（2026-11-10〜12）の型を参考にする。Adobe のデスクトップ制作ツールにネイティブの MCP 対応（プレビュー）が入り、OpenAI・Anthropic のモデルが Photoshop や Illustrator を会場の実演で操作した。Firefly はマルチモデルの制作スタジオへ広がり、Firefly Design（ベータ）、ノーコードの Firefly Builder（非公開ベータ）、再利用できるノード型ワークフローの Firefly Graph（公開ベータ）が加わった。企業向けには GenStudio に CX Enterprise Coworker と、ブランド基準を守らせる Brand Intelligence が入る。運用の型としては、制作の手順を Firefly Graph のような再利用ワークフローとして残し、ブランドの色・書体・表現の基準を Brand Intelligence に預けて、エージェントの出力に毎回同じ基準を当てさせる。
- 何が新しくなったか: 制作ツールが「人の手で操作するアプリ」から「エージェントが MCP 経由で呼ぶ部品」へ進んだ。再利用ワークフローとブランド基準の仕組みが、制作の再現性を支える土台になった。
- 出典: https://futurumgroup.com/insights/adobe-max-2026-adobe-ready-to-let-other-ai-agents-run-its-apps/

## 7. CRMの乗り換えは、「現状の地図作りからAIに任せる」型にする

- 分野: 営業
- 何を楽にするのか: 旧 CRM からの乗り換えで、現状の使い方の調査と設計に数か月かかる状態をやめ、移行そのものを週単位で回せるようにする。
- 再現の仕組み: ServiceNow の Autonomous CRM Engine（2026-11-12発表）の型を参考にする。AI が今の CRM がどう使われているかを発見し、将来の業務の姿を設計し、ServiceNow CRM 上に展開し、稼働後のずれを監視する、という4段を回す。旧来の移行が数か月から数年かかるのに対し、週単位での展開をうたう。初期顧客として Datacom と Xactly が名乗りを上げている。現在は Controlled Availability で、拡充は2027年予定、価格は未発表とされる。運用の型としては、移行の前に「今の CRM の使い方の地図」を AI に作らせ、その地図を設計と展開の基準として残す。地図が残れば、移行後のずれの監視にも同じ基準を使える。
- 何が新しくなったか: CRM 移行が「人が現状を調べて設計する長期プロジェクト」から、「AI が地図作りから監視まで回す仕組み」へ進んだ。移行の進め方そのものが製品化された。
- 出典: https://futurumgroup.com/insights/can-servicenows-autonomous-crm-engine-break-salesforce-lock-in/

## 8. 内部統制の監視は、「人が点検する」から「エージェントがずれを見張る」型にする

- 分野: 法務・リスク
- 何を楽にするのか: 内部統制の点検を、人が定期的に表を見直す作業から、エージェントが常に監視してずれを見つける仕組みへ変える。
- 再現の仕組み: ServiceNow の Agentic AI for Continuous Controls Monitoring（2026-11-10発表、一般提供は2027年第1四半期予定）の型を参考にする。AI エージェントが統制の点検を設定し、結果を読み解き、ずれていたり失敗していたりする統制を見つける。運用の型としては、統制の点検項目を「何を・どの頻度で・どう判定するか」の一覧として固定し、エージェントには設定と読み解きを任せ、ずれの判断と対応は人の承認を挟む。点検の記録はエージェントの判断と一緒に残し、あとから監査でたどれるようにする。
- 何が新しくなったか: 内部統制が「定期的な人の点検」から「エージェントによる継続的な監視」へ進んだ。統制の仕事が、表の確認から、ずれへの対応へ移る。
- 出典: https://www.ad-hoc-news.de/boerse/news/corporate-news/servicenow-stock-expands-ai-monitoring-to-enterprise-controls/70498297

## 9. AIの利用は、「モデルごと」ではなく「1つの関所」で統制・節約する型にする

- 分野: ガバナンス・運用
- 何を楽にするのか: 部署ごとに増える AI の利用を、誰が・どのモデルやツールを・どれだけ使ったか分からない状態から、1か所で記録・制限・節約できる状態にする。
- 再現の仕組み: Axway の Amplify Platform（2026-11-12発表）の型を参考にする。AI の統制・API 管理・連携・承認済みツールの目録を1つにまとめる。AI Control Plane は AI への要求を1件ずつ記録し（応答したモデル・使ったデータ・要求した利用者）、簡単な仕事は安いモデルへ振り分け、過去の回答を使い回す。同社はこれでトークン費用を30〜40%減らせると見込むとしているが、この数字は独立に検証されていない。クラウド・オンプレミス・ソブリンクラウド・完全なエアギャップで動くとされる。運用の型としては、AI への入口を1つの関所に集約し、モデル選びの基準（安いモデルで足りる条件）と回答の使い回しの条件をあらかじめ決めておく。
- 何が新しくなったか: AI の統制が「モデルやツールごとの個別管理」から、「要求を記録し、安いモデルへ振り分け、回答を使い回す1つの関所」へ進んだ。費用の節約が、統制の仕組みと一体になった。
- 出典: https://wisevoter.com/world/2026/11/12/axway-amplify-platform-enterprise-ai-governance

## 10. 熟練者の接客は、「モデルの役割分担」で再現する型にする

- 分野: 小売・接客
- 何を楽にするのか: 店頭のスタイリストのような熟練者の判断を、オンラインの接客でも同じ品質で再現し、1つの商品探しから一式の提案へ広げる。
- 再現の仕組み: J.Crew の Style Advisor（2026-11-12発表、Anthropic の Claude で構築）の型を参考にする。まず Claude Fable 5.1（複雑で開かれた仕事向けのモデル）で「スタイリストのように考えるにはどう推論すべきか」を計画し、Claude Opus 5.5 と Claude Code で試作品を作り、社内の技術者が製品化した。本番では役割を分ける。Claude Sonnet 5.5 がスタイリスト役として応答の各段を決め、Claude Haiku 5.5 が短く焦点の定まった仕事を受け持って速く返す。提案はすべて自社のスタイリストが撮影用に作った一式の組み合わせから始まり、バランスの取り方などの判断の基準も自社のものを使う。発売時は米国の男女向けデスクトップ版で、購入履歴に基づく個別化は今後の予定とされる。運用の型としては、熟練者の判断を「計画するモデル・作るモデル・対応するモデル・速く返すモデル」に分け、それぞれの仕事と判断の基準を固定しておく。
- 何が新しくなったか: 熟練者の判断の再現が「1つのモデルに全部任せる」形から、「モデルごとの役割分担と自社の判断基準の組み合わせ」へ進んだ。試作から製品化までの進め方も、モデルを使い分ける型になっている。
- 出典: https://claude.com/resources/articles/j-crew-style-advisor-with-claude
