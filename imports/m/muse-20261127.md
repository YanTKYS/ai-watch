## 1. チケットの添付ファイルは、「要点を抜いてから人が見る」型にする

- 分野: サポート・IT運用
- 何を楽にするのか: ITの問い合わせチケットに貼られたスクリーンショットやエラー記録、設定ファイルを、担当者が1つずつ開いて読み解く手間を減らす。
- 再現の仕組み: Salesforce の Agentforce の自動ファイル分析（2026-11-24公開のリリースノート）の型を参考にする。インシデント・問題・変更依頼のチケットにファイルが添付されると、Agentforce が自動で要点を抜き出し、要約を作り、原因の候補と対応案を示す。運用の型としては、添付ファイルの受け取り方を「貼るだけ」に固定し、抜き出した要点・原因・対応案をチケットの定型の欄に残し、最終の判断と対応は人が行う段にする。なお公開資料に書かれているのは要点の抽出・要約・原因の特定・対応案の提示までで、対応の実行まで自動で行うとはされていない。
- 何が新しくなったか: チケット対応が「添付ファイルを人が読む」形から、「AIが要点を抜いたものから人が判断する」形へ進んだ。問い合わせの一次対応が、ファイルの中身を読む作業から、抜き出された要点を確認する作業に変わりつつある。
- 出典リンク: https://help.salesforce.com/s/articleView?id=release-notes.rn_it_srvcs_agentforce_parent.htm&language=en_US&release=264&type=5

## 2. 社内ITヘルプは、「チャットの会話の中で受ける」型にする

- 分野: サポート・IT運用
- 何を楽にするのか: 社員がITの困りごとを解決するために、ヘルプの画面を開き直したり、問い合わせの場所を探したりする手間を減らす。
- 再現の仕組み: Salesforce の Agentforce と ServiceNow の連携（2026-11-24公開のリリースノート）の型を参考にする。ServiceNow の IT Assistance Agent を Slack や Microsoft Teams の会話の中から使えるようにし、社員は会話の中でナレッジ記事を探し、サービスを依頼し、インシデントの報告と進捗確認、承認まで行う。AI が作る文面や項目の対応付けは、組織の言い回しや運用に合わせて調整できる。運用の型としては、ITヘルプの入口を「Slack・Teamsの会話」に固定し、定型の依頼と承認の流れをその会話の中で完結させる。なお同じリリースノートでは、IT用途の既製の AI 機能と MuleSoft for Flow のコネクターは、クレジットの制限なしに使えるとされている。
- 何が新しくなったか: 社内ITヘルプが「専用の画面へ行くもの」から、「普段の会話の中で受けるもの」へ進んだ。問い合わせの入口が1つにまとまり、依頼・確認・承認が同じ会話の流れに載るようになった。
- 出典リンク: https://help.salesforce.com/s/articleView?id=release-notes.rn_it_srvcs_agentforce_parent.htm&language=en_US&release=264&type=5

## 3. 文書・表・スライドは、「チャットの中で作る」型にする

- 分野: 資料作成
- 何を楽にするのか: 調査や相談のチャットから、Wordの文書・Excelの表・PowerPointのスライドへ移るときに、内容を貼り直したり、アプリを開き直したりする手間を減らす。
- 再現の仕組み: Microsoft の Office in Copilot（2026-11-17に Ignite 2026 で一般提供）の型を参考にする。Word・Excel・PowerPoint が Microsoft Copilot アプリの中で動き、チャットの隣で文書・表・スライドを作り、OneDrive に保存して同僚と共同編集する。作ったファイルは Microsoft 365 の権限・機密ラベル・コンプライアンスの管理をそのまま引き継ぐ。運用の型としては、資料づくりの起点を「Copilot のチャット」に固定し、作る場所と保存先と権限の扱いを Copilot の中にまとめる。なお Office in Copilot は Copilot のライセンスに含まれ、別枠の従量課金はないとされる。対象の有料 Copilot ライセンスと基礎のサブスクリプションが必要で、全世界への展開は11月中旬に完了し、Deferred リリースは12月初旬からとされる。
- 何が新しくなったか: 資料づくりが「アプリを開いて作るもの」から、「チャットの中で作り、そのまま保存・共有するもの」へ進んだ。Copilot のホーム（Chat と Cowork を1つにした画面）も同時に一般提供となり、会話と仕事の場が同じ画面に集まり始めた。
- 出典リンク: https://www.epcgroup.net/insights/microsoft-ignite-2026-day-1-announcements

## 4. モデル選びは、「労力の予算として決める」型にする

- 分野: 開発
- 何を楽にするのか: 開発のたびに「どのモデルが速いか・安いか・賢いか」を人が選び直し、モデルごとの癖に振り回される状態を減らす。
- 再現の仕組み: GitHub の Copilot Fusion の更新（2026-11-17発表）の型を参考にする。Fusion はモデルそのものではなく、依頼ごとにモデルと進め方を選ぶ仕組みで、開発者は Standard・High・Max の3つの労力の段から選ぶだけにする。進め方は Single（1つのモデルで進める）、Cascade（軽いモデルで下書きし、必要なら強いモデルへ上げる）、Critique（1つのモデルが作り、別のモデルが点検してから直す）の3通り。2026年11月17日の更新で、使える場所が github.com・Visual Studio・GitHub Mobile ベータへ広がり、段ごとのモデルも新しくなった（Max に Claude Sonnet 5.5、High に GPT-6.1 Terra、Standard に MAI-Code-2）。運用の型としては、「どの段を使うか」を仕事の重さで先に決め、組織のモデル方針に外れるモデルは Fusion が選ばないよう管理者が決めておく。料金は Fusion 自体にはなく、選ばれたモデルごとに標準料金で請求され、有料プランには2026年11月30日までモデル料金の30%引きがあるとされる。なお GitHub が示す Terminal-Bench 4.1 の数字（Fusion Max の解決率71.2%、Opus 5.5・Fable 5.2 より5.4ポイント上、費用は Fable 5.2 より88%安い）は同社の測定で、信頼区間は重なるとする指摘もある。
- 何が新しくなったか: 開発のモデル選びが「人が1つずつ選ぶもの」から、「労力の予算として段を決め、振り分けは仕組みに任せるもの」へ進んだ。Fusion は2026年10月28日に一般提供され、11月17日の更新で使える場所と段ごとのモデルが広がった。
- 出典リンク: https://github.blog/changelog/2026-11-17-github-copilot-fusion-updates-more-availability-benchmarks-and-models/

## 5. チャットと開発の利用量は、「1つの枠で見る」型にする

- 分野: ガバナンス
- 何を楽にするのか: ChatGPT での相談と Codex での開発で利用量の枠が別々だと、どちらがどれだけ使ったかが見えにくく、重い仕事が片方の枠を使い切って止まる問題を減らす。
- 再現の仕組み: OpenAI の ChatGPT と Codex の利用量の統合（2026年12月から）の型を参考にする。Plus・Pro・Business プランでは、ChatGPT と Codex の利用量がトークンで測る1つの枠になり、ChatGPT の Work のエージェント機能が本体の ChatGPT へ移るのに合わせて、会話・Work・深い調査・Codex が同じ枠から引かれる。軽い会話の Instant チャットだけは枠の外に残る。残量とリセットの時刻は「設定」→「利用量」でまとめて確認できる。運用の型としては、12月を境に「相談と開発で1つの枠」と決め、重い仕事を始める前に残量を確認し、枠を使い切ったときの対応（リセットを待つ・プランを上げる・クレジットを買う）を先に決めておく。なお OpenAI は枠の大きさをプランごとに公表しておらず、統合された Chat と Work の画面も2026年11月24日から一部の Pro ユーザーで試行が始まった段階とされる。Pro の利用量は2026年10月29日のリリースノートで切り下げが見送られ、Work と Codex の枠が引き上げられている。
- 何が新しくなったか: 利用量の見方が「製品ごとの別枠」から「相談と開発で1つの枠」へ変わった。会話と開発の境目がなくなる分、使う側は枠の残量を1つの数字で管理する形になる。
- 出典リンク: https://www.explainx.ai/blog/chatgpt-codex-usage-limits-merge-shared-token-allowance-december-2026

## 6. 機密データは、「暗号化したまま処理・監視する」型にする

- 分野: ガバナンス・セキュリティ
- 何を楽にするのか: 契約書や顧客情報、財務・人事の記録のように、外部の AI に送れない機密情報を扱う仕事で、AI を使うか使わないかの二択しかない状態を減らす。
- 再現の仕組み: OpenAI の Private Inference（2026-11-25にテスト開始が発表）と Anthropic の Enterprise Frontier Safeguards（2026-11-23に公開ベータ）の型を参考にする。Private Inference は、機密コンピューティングと検証できる厳格な管理で、プロンプトと回答をモデルが処理している間も守る仕組みで、現在は一部の顧客でのアルファ段階のテストとされる。Enterprise Frontier Safeguards は、プロンプトと回答を顧客自身の Amazon S3・Google Cloud Storage のバケットへ自社の暗号鍵で暗号化して置き、Anthropic もクラウド事業者も写しを残さない。悪用の監視は自動で行い、疑わしい動きがあれば内容を含まない Safety Case を顧客のチームへ出し、7日以内に確認する決まりにする。運用の型としては、機密情報の置き場所（自社のバケット）と鍵の管理、監視で上がった案件への対応期限を先に決め、AI に送る前の判断を「送ってよい情報かどうか」ではなく「どの守り方で送るか」で行う。なお Private Inference は対応モデル・料金・一般提供の時期が未公表。Enterprise Frontier Safeguards は EFS 自体の料金はなく、Messages API のみが対象で、Files API・Batch・Managed Agents は対象外、HIPAA 対応のワークスペースも対象外とされる。
- 何が新しくなったか: 機密データの扱いが「AI に送らない」か「送って残るのを許す」かの二択から、「暗号化したまま処理・監視する」形へ進んだ。2社が同じ週に、データをベンダー側に残さない守り方を打ち出した。
- 出典リンク: https://www.cnbctv18.com/technology/sam-altman-announces-openai-private-inference-whats-the-new-privacy-feature-and-how-does-it-work-20041890.htm
- 出典リンク: https://www.techrepublic.com/article/news-anthropic-claude-misuse-monitoring-zero-data-retention/

## 7. AIの課金は、「既定値と上限を期限前に決める」型にする

- 分野: 開発・ガバナンス
- 何を楽にするのか: AI の従量課金が「既定のまま」で動き出し、気づかないうちに組織の請求が増えたり、急に止まったりする状態を減らす。
- 再現の仕組み: GitHub と Atlassian の課金の既定値の変更（どちらも2026年12月が期限）の型を参考にする。GitHub は2026年12月30日から、Copilot code review の課金先の選択が保存されていない組織では、有料 Copilot ライセンスを持つ人のレビューをリポジトリを持つ組織へ請求する。今は未選択だとその人の Copilot の枠から引かれる。現状を保ちたい管理者は12月30日までに組織・企業の Copilot ポリシーで Member を選ぶ。組織への請求には AI Credits の有料利用が必要で、支出が増える場合があるとされる。レビュー1件あたりの目安は Lite 約0.25ドル、Balanced（既定）約1.50ドル、Max 約10ドルとされる。Atlassian は2026年12月3日から、Rovo クレジットと Jira 自動化のステップが、組織で共有する月ごとの枠を超えた分を課金する。超えた分は Rovo クレジット1件0.01ドル、自動化ステップは1,000件あたり0.50ドル。超過時の課金は既定で有効になっており、管理者は12月3日までに支出の上限を決めるか、超過時の課金を切って枠を超えたら止まるようにする。枠の残量は80%と100%で通知が来る。運用の型としては、AI の課金の「誰が払うか」と「上限はいくらか」を、期限の前に一覧で決め、既定任せの項目が残っていないかを確認する段を入れる。
- 何が新しくなったか: AI の課金が「使った分だけ後から請求されるもの」から、「既定値と上限を期限前に決めておくもの」へ進んだ。12月3日と12月30日という2つの期限が、確認のきっかけになっている。
- 出典リンク: https://github.blog/changelog/2026-11-25-copilot-code-review-billing-will-default-to-the-organization/
- 出典リンク: https://www.catapultlabs.com/blog/rovo-credits-jira-automation-limits-checklist

## 8. 定型の依頼は、「時間で動くタスクとして残す」型にする

- 分野: 業務全般
- 何を楽にするのか: 毎朝の要点まとめや週1回の集計のように、同じ依頼を毎回チャットに書き直す手間と、頼み忘れて回らなくなる問題を減らす。
- 再現の仕組み: Microsoft 365 Copilot の定型プロンプトからスケジュール済みタスクへの移行（2026-11-12に Message Center MC1550533 で案内）の型を参考にする。これまでの定型プロンプトは Power Platform 上で動いていたが、2026年12月31日に終了して止まるため、残したいものは Copilot アプリの「タスク」→「スケジュール済み」で作り直す。新しいタスクは Copilot の仕組みの中で動き、Power Automate が無効でも動き、データは Microsoft 365 のコンプライアンスの範囲の中で処理・保存される。1人あたり有効なタスクは10件まで、合計50件までとされる。運用の型としては、定型の依頼を「いつ・どれくらいの頻度で・何を返すか」のタスクとして残し、期限前に古い定型プロンプトの棚卸しをして、要るものだけ作り直す。なお展開は Frontier が2026年11月11日から、全世界は2026年11月30日から12月31日にかけてとされ、スケジュール済みタブが出てから30日間は古いメニューからも開けるとされる。
- 何が新しくなったか: 定型の依頼が「Power Platform に載ったプロンプト」から、「Copilot の中で時間で動くタスク」へ進んだ。2026年12月31日という終了日が付いたため、残すかどうかの判断が先に求められる形になった。
- 出典リンク: https://mc.merill.net/message/MC1550533

## 9. 社外の人のログインは、「1人ずつ例外を決める」型にする

- 分野: ガバナンス
- 何を楽にするのか: 取引先や外部の協力者を ChatGPT のワークスペースへ招くたびに、シングルサインオン（SSO）の扱いが人によってばらつき、入れない人や想定外に入れる人が出る問題を減らす。
- 再現の仕組み: OpenAI の ChatGPT の外部メンバー向け SSO 例外の設定（2026-11-19のリリースノート）の型を参考にする。外部メンバーとは、そのワークスペースが確認していないドメインのメールアドレスを持つ人のことで、ワークスペースの所有者が管理コンソールの「メンバー」から1人ずつ「SSO なしでのログインを許可」か「ワークスペースの SSO 方針に従う」かを決める。新しい外部メンバーは既定で SSO 方針に従い、SSO が必須のワークスペースでは SSO を使わなければ入れない。すでにいた外部メンバーは、アクセスを保つための例外が自動で付いている。運用の型としては、外部の人を招くときに「SSO を使うか・例外にするか」を1人ずつ記録し、定期的に各メンバーの設定を確認する。なお例外はそのワークスペースだけに適用され、退会や削除で消え、再招待では戻らない。設定の変更は所有者だけができ、管理者は確認だけできる。
- 何が新しくなったか: 社外の人のログインが「ドメイン未確認なら一律に SSO を外せる」形から、「1人ずつ例外を決める」形へ進んだ。外部の協力者を招くときの判断が、ワークスペースごとの記録として残るようになった。
- 出典リンク: https://help.openai.com/en/articles/9534785-single-sign-on-sso-setup-for-openai-products
