## 1. 無人で回すコーディングエージェントは、「許可待ちで止まらない設定」と「長い処理は裏で走らせる」型にする

- 分野: 開発・運用
- 何を楽にするのか: 夜間や長時間のエージェント実行が、許可ダイアログ待ちや重いツール呼び出しで止まる問題をなくす。
- 再現の仕組み: Claude Code 2.1.319（2026-11-06）の2つの設定を固定する。`permissions.denyInsteadOfPrompting` を有効にし、許可待ちになる呼び出しは即座に却下して処理を続けさせる。MCPサーバーがタスクとして実行するツール呼び出しは自動でバックグラウンドに回り、完了時に結果が通知される（`CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND` で従来の待ち動作に戻せる）。無人実行では、事前に許可するツールだけを明示し、それ以外は却下して続行する、という運用ルールとして残す。
- 何が新しくなったか: これまでMCPの長い処理はセッションを占有していたが、2.1.319でターミナルでもバックグラウンド実行に対応し、Bedrock・Vertex・Foundry・LLMゲートウェイ経由でも使えるようになった。あわせて、オートモードがゲートウェイ越しでサーバー確認できない呼び出しを問い合わせ・却下するよう締め付けが強まった。
- 出典: https://code.claude.com/docs/en/changelog

## 2. エージェントは、Teamsの中に「埋め込む」形で届ける

- 分野: 開発・運用
- 何を楽にするのか: 社員が新しい画面を覚えずに、普段使うTeamsからエージェントに仕事を頼めるようにする。
- 再現の仕組み: Google ADK 2.14.0（2026-11-07）の `TeamsRunner` を使う。エージェントの定義はADKのコードのまま変えず、実行の入口だけTeamsにする。評価は `MultiRunConfig` で同じ評価を並行に繰り返し実行し、結果を比べられる形にする。2.14.0では認証・実行環境・評価まわりの26モジュールが実験段階から安定版に上がったため、社内向けの本番利用の土台として固定しやすい。
- 何が新しくなったか: ADK 2.14.0でTeams連携が追加され、30ノード規模の長いワークフローが23%速く、ピークメモリ9%減とされる（Googleの発表値で、比較条件の詳細は未公開）。セマンティックなツール引数マッチングも加わり、評価の並行実行が可能になった。
- 出典: https://emergent.sh/news/google-adk-2-14-adds-teams-integration-multi

## 3. エージェントの定義は1つに書き、動かす場所だけ3通りから選ぶ

- 分野: 開発・運用
- 何を楽にするのか: 開発時の手元実行と本番の管理実行でエージェントの作り直しが発生する手間をなくす。
- 再現の仕組み: Mistral Studio（2026-11-05発表）の Agents SDK（Pythonパッケージ `mistralai-agents`）でエージェントをコードとして定義する。同じ定義を、自分のプロセス内・自社サーバー（`agents serve`）・Mistral管理の実行基盤（`agents deploy`）の3通りで動かす。スキル・サンドボックス・サブエージェント・フックを定義に含め、ツールやデータへの到達範囲を境界として明記する。ワークフローは「決まった手順・推論・人の判断」を組み合わせた耐久実行として別に定義し、中断しても途中から再開できる形にする。アプリはログインとアクセス制御付きでホストする。
- 何が新しくなったか: Mistral Studioに Managed Agents と Apps が公開プレビュー、Workflows が提供開始となった。ワークフローはイベント起点で起動でき、視覚的なグラフで流れを確認できる。プライベートクラウド・オンプレミスは11月末からの提供予定。なお、旧 Agents API は非推奨となり、新規は Agents SDK で作る流れに変わった。
- 出典: https://www.datastudios.org/post/mistral-studio-managed-agents-workflows-apps-public-preview

## 4. 業務用語の定義を1か所に集め、エージェントの答えを「承認済みの言い方」にそろえる

- 分野: 調査・分析
- 何を楽にするのか: エージェントや社員が同じ指標・用語を別々に解釈して、数字や答えが食い違う問題を減らす。
- 再現の仕組み: Snowflakeの Business Ontology（2026-11-03発表）の考え方を借りる。業務用語・関係・所有者を承認済みの定義として1か所にまとめ、セマンティックビューやテーブルと紐づける。エージェントはこの定義を参照して答えるため、「売上」のような言葉の意味が部署ごとに変わらない。用語集はオーナー付きで管理し、変更は承認を経て1か所だけ直す。
- 何が新しくなったか: Snowflake Expedition 2026で Business Ontology が発表され、エージェントに業務文脈を与える仕組みとして位置づけられた。あわせて Cortex AI Gateway が拡張され、ツール呼び出しの認可・プロンプトインジェクション対策・コスト管理・モデル振り分けを一か所で統制できる。Business Ontology は発表時点では公開プレビュー開始前で、Gateway の一部機能もプライベートプレビュー段階のため、導入は提供状況を確認してから進める。
- 出典: https://analyticsindiamag.com/ai-news/snowflake-introduces-business-ontology-cortex-ai-gateway-to-bring-ai-agents-into-enterprise-workflows

## 5. 定例の仕事は、頼むたびに起動するのではなく「常駐ボット」に任せる

- 分野: 開発・業務
- 何を楽にするのか: 毎回同じ依頼を出して待つ手間をなくし、定例作業を裏で回り続ける仕組みにする。
- 再現の仕組み: Snowflakeの CoCo / CoWork Bots（2026-11-03発表）の型を参考にする。繰り返し実行したい作業を CoCo Automations として一度定義してスケジュールし、さらに広い目標は常駐ボットに渡して裏で進めさせ、判断や承認が必要なときだけ人に声をかける。長い多段階の作業は Async Agent API で中断しても途中から再開できる形にする。チーム内で作ったスキルやプラグインは共有し、統制付きで再利用する。
- 何が新しくなったか: これまで対話のたびに起動していた CoCo（データチーム向けコーディングエージェント）と CoWork（知識労働者向けエージェント）に、常駐して自律的に働く Bots が加わった。Snowflake Mobile からは外出先でも承認や進捗確認ができる。動的モデル振り分けにより、作業ごとに適したモデルを自動で選ぶ仕組みも入った。
- 出典: https://www.hpcwire.com/bigdatawire/this-just-in/snowflake-adds-autonomous-bots-to-coco-and-cowork-ai-agents/

## 6. 個人のエージェントには「目標」と「承認の関所」を先に決めて渡す

- 分野: 営業・法務・サービス
- 何を楽にするのか: 社員一人ひとりの定例・フォロー作業を、指示を出すたびに付き添わずに回す。
- 再現の仕組み: Microsoft 365 Copilot の Autopilot（2026年11月に Frontier へ展開）の型を参考にする。エージェントには手順ではなく目標を渡し、自分のメールボックス・ファイル・作業場所を持たせてクラウドで常駐させる。重要な操作の前には承認の関所を置き、IT側は Agent 365 で「誰が・何を・どこまで」を管理する。あわせて Cowork の職種別プラグイン（営業・サービス・法務・財務）を使い、商談準備・問い合わせ振り分け・プレイブックに沿った契約レビューなど、職種ごとの定型スキルをあらかじめ用意する。
- 何が新しくなったか: Copilot が「質問に答える道具」から「仕事を預ける相手」へ変わる大型更新で、Home（Chat と Cowork を並べた起点）・Code（自然言語でトラッカーやアプリを作る画面）とともに Autopilot が加わった。Cowork は OneNote・Planner とも連携し、承認を得てメモや計画を更新できる。Autopilot は11月時点では Frontier（早期アクセス）への展開段階で、一般提供ではない。
- 出典: https://www.changingsocial.com/blog/whats-new-in-microsoft-copilot-november-2026/

## 7. エージェントの安全確認は、「攻撃側の推論」で試すレッドチームと「費用と品質を結ぶ」観測で回す

- 分野: セキュリティ・運用
- 何を楽にするのか: エージェントの脆弱性確認とコスト管理を、場当たりのチェックから継続的な仕組みにする。
- 再現の仕組み: Cisco AI Defense の発表（2026-11-09）の型を参考にする。レッドチームは定型の攻撃リストではなく、フロンティア級の推論で多段階の攻撃経路を生成して試す。観測は Splunk Agent Observability に集め、エージェントの実行記録（トレース）と専門家のフィードバックから評価用の小規模モデルを作り、評価とガードレールを低コストで回す。費用管理は Tokenomics の考え方で、エージェント1件あたりの費用を仕事の品質評価と結びつけ、費用対効果をリアルタイムで見る。
- 何が新しくなったか: Cisco AI Defense の適応型レッドチームに Anthropic の Claude Mythos が加わり、エージェントへの現実的な攻撃を推論で再現できるようになった。評価モデルは商用LLMより最大98%低コストで評価を実行できるとされる。Tokenomics は12月にプライベートプレビュー、2027年初に AWS Marketplace で一般提供の予定で、レッドチーム機能も一部企業向けに順次提供。
- 出典: https://newsroom.cisco.com/c/r/newsroom/en/us/a/y2026/m11/cisco-unveils-frontier-ai-red-teaming-and-agent-observability-to-secure-the-agentic-enterprise.html

## 8. 運用の監視は「アラートへの反応」ではなく「目標を持った常駐の見張り」に変える

- 分野: 運用・監視
- 何を楽にするのか: リリース後の不具合や計測の抜けを、人が気づいてから動くのではなく、裏で見張る仕組みで早くつかむ。
- 再現の仕組み: Honeycomb の AI SRE Agents（2026-11-03発表）の型を参考にする。エージェントにはアラートではなく目標を渡す。「リリース後30分はチェックアウトサービスの遅延とエラーを確認する」「計測の改善案を定期的に出す」など、目的・きっかけ（デプロイ・スケジュール・SLO）・報告先を決めておく。調査のたびに得た知見は共有の記憶として残し、次の調査に引き継ぐ。見つけた内容はすべて、根拠となるクエリ・トレース・デプロイへのリンク付きで返し、「測定済み・推定・未確定」を区別する。
- 何が新しくなったか: Personal Agent（個人向け）と Team Agents（チーム向け）が早期アクセスで登場し、Team Agents は2026-12-01に一般提供の予定。あわせて AI Ecosystem が発表され、稼働中の全エージェントの失敗率・コスト・会話を一望できる。Team Agents は稼働時間ベースの課金になる見込み。
- 出典: https://www.honeycomb.io/blog/honeycomb-introduces-ai-sre-agents

## 9. 表計算のAI入力は、「セルごとの出典」を残して検証できる形にする

- 分野: 資料作成・経理
- 何を楽にするのか: AIが埋めた表の数字を、根拠をたどらずに信じ込んでしまう危うさをなくす。
- 再現の仕組み: Google Sheets の Fill with Gemini（2026-10-28からの変更）の型を参考にする。AIにセルを埋めさせるときは、セルごとに参照したWeb出典を表示させ、1回の要求は最大3,000セルまでに区切る。資料作成では、Geminiアプリ内でファイルを作ってその場でプレビュー・修正する流れ（2026-10-29開始）にし、スライドは「複数スライドや資料全体を一度に変更する」「参考ファイルに様式を合わせる」指示を定型化する。いずれも、出力の事実・数式・出典は人が確認してから使う運用にする。
- 何が新しくなったか: Sheets の AI入力にセルごとの出典表示が加わり、どの情報源から来た数字かが確認できるようになった。Geminiアプリでは文書・表計算・スライド・PDF・Markdown・コードを会話の中で作って編集できるようになり、Slidesでは資料全体の一括変更や Drive のファイルを使った拡張ができるようになった（スライドの一括変更は当面英語のみ）。なお Gemini 2.5 は2026-12-01に API で提供終了となり、自動で後継モデルへ切り替わるため、2.5に依存した連携は事前に確認が必要。
- 出典: https://hellogrowth.ai/en/blog/google-ai-news-november-2026

## 10. 機密性の高い推論と大規模コンテキストは、用途で計算基盤を分ける

- 分野: 開発基盤
- 何を楽にするのか: 機密データを扱う推論と、コードベース全体や長時間動画のような大きな入力を、同じ基盤に無理に載せて妥協するのをやめる。
- 再現の仕組み: Google の第8世代TPU拡張（2026-11-09発表）の型を参考にする。機密推論には TPU 8tx（セキュリティ強化）、大規模コンテキストと高密度計算には TPU 8i Max と、用途で基盤を分けて選ぶ。ソフトウェア側は TorchTPU や TPU Sync など、使うスタックを用途ごとに固定しておく。社内では「機密推論はこの基盤」「大規模入力はこの基盤」という選択表として残す。
- 何が新しくなったか: 第8世代TPUポートフォリオに、機密推論向けの TPU 8tx と、大規模コンテキスト・高密度計算向けの TPU 8i Max が追加された。エージェント時代の実行基盤として、安全性と規模の両面が強化された。
- 出典: https://x.com/Google/status/2119788086490001906
