## 1. 長時間の開発は、「仕様・実装・評価を3つのエージェントに分ける」型にする

- 分野: 開発
- 何を楽にするのか: 1つのエージェントに長い開発を任せると、作ったものを自分で「できた」と評価してしまい、ズレに気づかないまま進む問題を減らす。
- 再現の仕組み: Anthropic Labs の三エージェントハーネス（2026-11-27に解説が共有）の型を参考にする。Planner が仕様書を書き、Generator がスプリントごとに作り、Evaluator が Playwright で実際に動かして確かめる。3つの役を分け、スプリントごとの契約（何を作るか・何をもって完了とするか）と硬い評価基準を先に決め、作った本人が評価しない段にする。運用の型としては、長い開発を「仕様を書く」「作る」「動かして確かめる」の3つの役に分け、各スプリントの完了条件を文章で残し、評価は作り手とは別の役が行う。なお共有された解説は第三者によるもので、公式資料との照合が望ましいとされる。
- 何が新しくなったか: 長時間のエージェント開発が「1つのエージェントに任せきり」から、「仕様・実装・評価を分けて、自己評価を防ぐ」形へ進みつつある。
- 出典リンク: https://x.com/slash1sol/status/2125981601905398264

## 2. 広告とアクセス解析は、「1つの会話で扱い、変える前に承認を取る」型にする

- 分野: マーケティング
- 何を楽にするのか: 広告キャンペーンの確認とアクセス解析を別々の画面で開き、数字を貼り合わせて判断する手間を減らす。
- 再現の仕組み: Grok Bot の Google Ads・Google Analytics 連携（2026-11-28に報告。すでに使えた Google Search Console と合わせて3つの Google サービス）の型を参考にする。自然言語で広告キャンペーンやトラフィックを1つの会話の中で扱い、変更を加える前にはユーザーの承認を求める。運用の型としては、広告と解析の入口を「1つの会話」にまとめ、「見るだけ」と「変える」を分け、変える段では必ず人の承認を挟む。なお第三者による報告で、公式の確認は取れていないとされる。
- 何が新しくなったか: マーケティングの数字の扱いが「画面を渡り歩いて集めるもの」から、「1つの会話で聞いて、変える前に承認を取るもの」へ進みつつある。
- 出典リンク: https://x.com/XFreeze/status/2126337799460995383

## 3. プロジェクトの危うさは、「兆しを見つけて人が動く前に知らせる」型にする

- 分野: 営業・プロフェッショナルサービス
- 何を楽にするのか: プロジェクトの予算・日程・顧客関係の危うさに、人が気づいたときには手遅れになっている問題を減らす。
- 再現の仕組み: Kantata の Signals・Knowledge Graph・Expertise Engine（2026-11-27発表）の型を参考にする。Signals がプロジェクト・予算・日程・顧客関係の変化からリスクや好機の兆しを先に見つけ、Knowledge Graph が過去の案件・文書・会話とつないで背景を示す。Expertise Agent が1つの会話口で聞き、Agent Studio で自社の納品の基準やベストプラクティスを管理されたカスタムエージェントに落とす。運用の型としては、兆しの検知と背景の提示を仕組みに任せ、対応の判断は人が行い、組織の基準は Agent Studio のような「型」として残す。なお Signals は来年前半の提供とされ、まだ使える段階ではない。
- 何が新しくなったか: プロジェクト管理が「人が数字を見て危うさに気づくもの」から、「仕組みが兆しを先に知らせるもの」へ進みつつある。
- 出典リンク: https://www.kmworld.com/Articles/ReadArticle.aspx?ArticleID=177667

## 4. 大きな書き換えは、「本番そのものを検証役にする」型にする

- 分野: 開発
- 何を楽にするのか: 稼働中のシステムを別の言語へ書き換えるとき、書き換え自体より「新しいものが古いものと同じ動きをするか」の確かめに手間と時間がかかる問題を減らす。
- 再現の仕組み: Anthropic の Claude Messages API の Python から Rust への移行（2026-11-26に同社が公開）の型を参考にする。Claude がコードの8割超を約1週間で書き、検証は本番の API そのものを検証役にして行った。本番の通信を新旧の両方に通して違いを比べ、違いの記録をエージェントへ渡して直す。内側の速い検証ループ（サンドボックスで仮説を試す）、外側の遅い検証ループ（本番で直したものを確かめる）、過去の間違いをためて次のエージェントへ渡す記憶のループの3つを回し、人は「何が正しいか」の判断だけを受け持つ。結果は CPU が約70%減、メモリが約80%減、最初の応答までの中央値が約20%改善し、停止なしで移行したとされる。運用の型としては、書き換えの前に「何をもって同じ動きとするか」と、違いを見つける仕組み・直す段・間違いをためる場所を先に決める。
- 何が新しくなったか: 大きな書き換えの難所が「コードを書くこと」から「動きが同じだと確かめること」へ移った。検証のループを回す形が、書き換えの再現できる型になりつつある。
- 出典リンク: https://www.infoworld.com/article/4253460/anthropic-says-it-moved-its-claude-api-from-python-to-rust-with-no-downtime.html

## 5. エージェントの実行は、「仕事ごとに隔離した機械で動かす」型にする

- 分野: 開発・ガバナンス
- 何を楽にするのか: エージェントが作ったコードをそのまま動かすと、意図しない操作がホストや他の仕事へ広がる恐れがある問題を減らす。
- 再現の仕組み: Microsoft の AKS Agent Sandbox と Agent Grid（Ignite 2026、2026-11-17発表、プレビュー段階）の型を参考にする。エージェントが作ったコードは、仕事ごとに区切ったマイクロVM（AKS Agent Sandbox）の中で動かし、終われば消える。Agent Grid がエージェント同士・サービス間の通信を、身元に基づく既定拒否の通信規則と相互 TLS で縛り、行ける先を先に決める。運用の型としては、エージェントの実行場所を「隔離した機械」に固定し、通信できる先の一覧と、使い捨ての短い有効期限の資格情報を先に決める。なおどちらもプレビュー段階で、本番での利用条件や文書はまだ整っていないとされる。
- 何が新しくなったか: エージェントの実行が「同じ場所で動かすもの」から、「仕事ごとに隔離した機械で動かし、通信も縛るもの」へ進みつつある。
- 出典リンク: https://www.techtarget.com/news/microsofts-azure-upgrades-add-speed-and-security-to-agents/875110/

## 6. 社内の端末で LLM を動かすときは、「重みを1ビットにして CPU で回す」型にする

- 分野: 現場・閉域
- 何を楽にするのか: GPU のない業務端末や古いサーバーでは LLM が動かせず、生成AIの試行が端末の更新待ちになる問題を減らす。
- 再現の仕組み: Microsoft の BitNet（1ビット LLM「BitNet b1.58」用の公式推論エンジン）の型を参考にする。重みを1.58ビット（-1・0・1の3値）で表し、x86 CPU で2.37〜6.17倍の高速化と71.9〜82.2%の省電力をうたう。100B の大型モデルでも CPU 1つで人が読む速さ（毎秒5〜7トークン）で動くとされる。2026年7月には1ビットの埋め込みモデル（0.6B・270M）も公開された。運用の型としては、閉域の端末で動かす処理を「要約・分類などの定型作業」から試し、使うモデルは1ビット専用に学習されたものに限る。なお日本語の性能は未知数とされる。
- 何が新しくなったか: 閉域の LLM が「GPU を積んだ特別な機械で動かすもの」から、「手元の CPU で動かすもの」へ進みつつある。
- 出典リンク: https://github.com/microsoft/BitNet

## 7. 会議の文字起こしは、「閉域の端末で完結する単体の道具」にする

- 分野: 議事録
- 何を楽にするのか: 会議の録音を外部の文字起こしサービスへ送る手間と、外部へ出せない録音を扱えない問題を減らす。
- 再現の仕組み: whisper.cpp（Whisper の C/C++ による軽量実装、v1.9.6 は2026-11-23公開）の型を参考にする。CPU だけで動き、無音区間の検出（VAD）にも対応し、単体の実行ファイルで動くため、既存の内製ツールから外部プロセスとして呼び出せる。運用の型としては、録音から下書きまでの処理を閉域の端末に閉じ、作った下書きは人が校正する段を残す。なお日本語の精度は使うモデルの大きさ（tiny〜large）で大きく変わるとされる。
- 何が新しくなったか: 会議の文字起こしが「外部サービスへ送るもの」から、「閉域の端末で完結する道具」へ進みつつある。
- 出典リンク: https://github.com/ggml-org/whisper.cpp

## 8. 手元のメモ・議事録は、「端末の中で探せる検索エンジン」に置く

- 分野: 調査・分析
- 何を楽にするのか: 担当者の手元の業務メモ、引き継ぎ書、文字起こしした議事録が散らばり、必要な記述を探し出せない問題を減らす。
- 再現の仕組み: qmd（ローカルの Markdown 検索エンジン、v2.9.0 は2026-11-18公開）の型を参考にする。Markdown のメモ・会議の文字起こし・マニュアルを索引化し、キーワードでも自然な文章でも探せる。全文検索（BM25）・意味検索・LLM による並べ替えを組み合わせ、すべて端末の中で動く。MCP サーバーとして AI エージェントからも使え、待ち受けは既定で自分の端末（localhost）だけ。運用の型としては、探す対象を「手元の Markdown と文字起こし」に決め、whisper.cpp で文字起こしした結果をそのまま検索対象に入れる。なお既定の埋め込みモデルは日本語への対応が弱いとされ、多言語対応のモデルへの切り替えが要る。閉域ではモデルを事前に取得して置く必要がある。
- 何が新しくなったか: 手元の知識の探し方が「フォルダを開いて目で探すもの」から、「端末の中で意味でも探せる検索」へ進みつつある。
- 出典リンク: https://github.com/tobi/qmd

## 9. 帳票の表は、「Webアプリに組み込んでエージェントが直接書き換える」型にする

- 分野: 資料作成・経理
- 何を楽にするのか: Excel で管理する台帳や集計表がファイルで散らばり、版が分かれて転記に手間がかかる問題を減らす。
- 再現の仕組み: Univer（表計算・文書編集の機能を Web アプリに部品として組み込む SDK、v1.6.2 は2026-11-25公開）の型を参考にする。数式エンジン・描画・取り消し・やり直しを備えた Excel に近い画面を庁内 Web アプリに組み込み、API を通じて外部のアプリや AI エージェントが表の内容を直接読み書きする。運用の型としては、台帳の置き場所を「Web アプリの中の1つの表」に決め、「申請データを台帳に転記し、集計式を更新する」流れをエージェントに任せ、結果は表の履歴として残す。なお共同編集やサーバー側の処理など一部は商用ライセンスとされ、オープンソースの範囲でできることを先に確認する必要がある。UI は日本語に対応。
- 何が新しくなったか: 帳票の扱いが「Excel ファイルを渡して転記するもの」から、「Web アプリの中の表をエージェントが直接書き換えるもの」へ進みつつある。
- 出典リンク: https://github.com/dream-num/univer

## 10. LLMの仕組みの研修は、「小さなモデルを2時間で一から学習させる」型にする

- 分野: 人事・研修
- 何を楽にするのか: LLM の仕組みを説明だけでは身につかず、大きなモデルの学習は職員の手元の環境では重すぎて試せない問題を減らす。
- 再現の仕組み: minimind（64M パラメーターの小さな LLM を2時間で一から学習させる教材）の型を参考にする。小さなモデルを実際に学習させることで、学習の流れ・推論の動きを手で確かめられる。運用の型としては、研修の題材を「小さなモデルを一から育てる」体験に決め、説明の資料と学習の手順・結果をセットで残し、同じ研修を繰り返し行える形にする。
- 何が新しくなったか: LLM の仕組みの学び方が「説明を聞くもの」から、「小さなモデルを実際に育てて確かめるもの」へ進みつつある。
- 出典リンク: https://github.com/jingyaogong/minimind
